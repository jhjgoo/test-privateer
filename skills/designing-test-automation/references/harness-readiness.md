# 轻量六段式 Harness

Harness 是测试者准备目标、施加刺激、观察结果、保留证据并恢复资源的最小支撑能力。它是能力约定，不是六个脚本、六个目录、统一服务或新测试框架。

## 六段能力

| 段 | 要回答的问题 | 典型证据 |
| --- | --- | --- |
| `Prepare` | 测试什么、用什么身份、什么输入和初始数据？ | 目标版本、身份来源、夹具或数据指针 |
| `Start` | 如何启动或连接目标，如何知道它可测？ | 启动入口、连接信息、只读 doctor 或就绪检查 |
| `Drive` | 如何施加真实测试刺激？ | 函数调用、HTTP 请求、浏览器操作、Agent 任务或命令 |
| `Observe` | 独立预期是什么，实际结果在哪里看？ | 业务状态、响应、渲染状态、文件变化、轨迹或日志 |
| `Preserve` | 原始证据如何在清理后仍可复核？ | 脱敏响应、截图、视频、日志、轨迹和哈希指针 |
| `Restore` | 只清理哪些本轮资源，如何处理失败残留？ | teardown、数据回滚、端口／会话释放和残留说明 |

同一 Runner 可以覆盖多段。纯函数、只读检查或当前目标不涉及的段可以明确记录 `not_applicable`；不得为了形式完整新增无价值基础设施。

## 长期状态

测试表面的 Harness 只使用以下六个状态：

- `not_configured`：没有项目约定或可定位入口。
- `partial`：有部分能力，但至少一段会影响当前执行安全、观察、证据或恢复。
- `declared_unverified`：项目已声明入口或选择，但当前快照没有足够实际证据。
- `verified`：六段均有适用的入口或明确不适用项，且至少一条真实目标路径提供了驱动、独立观察、原始证据和清理后回读证据。
- `blocked`：权威来源冲突、授权／隔离／安全前置无法满足，当前不能安全继续。
- `not_applicable`：有项目来源或用户决定说明该表面当前不适用。

`verified` 只描述 Harness 能力，不代表产品通过、全量覆盖、CI 已接入或当前 Run 已完成。不存在第七个 `stale` 状态；版本、入口、规则或环境边界变化使旧证据失效时，按当前缺口使用 `declared_unverified`、`partial` 或 `blocked`，同时保留历史证据指针。

## 来源与采纳边界

发现测试文件、脚本、依赖或命令不等于项目已经选择它。项目权威规则、正式文档、构建／CI 入口或用户明确确认才能支持“已选定”；Git 提交本身也不自动证明当前项目仍采用该入口。

分别核对**本轮执行授权、实际验证证据和长期采纳**。用户已授权生成或运行临时驱动时，可以在该范围内试验；未提交、临时或 AI 生成本身不是禁令。未知历史脚本仍先核对来源、执行范围和安全边界，不因文件存在就运行。只要求设计或只编写时不执行。

本轮实测可以返回一次性 `verified`，但未经项目权威来源或用户采纳，不写成长期入口或项目 Harness `verified`。一次通过不等于长期采纳；采纳会改变后续执行且没有既有决定时，说明影响再确认，不先写入长期配置。

## 框架与入口选型

已有合适项目框架或用户指定入口时直接沿用；用户明确委托选型时，在约定范围内选择并说明依据。无约定也无委托，且选择会实质改变长期依赖、维护方式、费用或执行边界时，给出最少候选、推荐和影响并等待确认。既有栈内选择客户端或标准库临时探针，不自动升级为长期框架决定，也不强制先做完整 Setup。

选型委托不自动授权安装、联网、付费、替换既有套件或产品执行；逐项沿用当前已有效的授权，不重复询问已确认事项。框架专项只在选择有上述依据后加载。

## 按表面裁剪

- **单元**：`Prepare` 可以是函数输入和隔离夹具，`Start` 可以是 Runner 初始化；不需要服务启动时明确不适用。`Observe` 必须是独立断言，`Preserve` 保留失败输出，`Restore` 清理 mock、临时文件或状态。
- **接口**：准备身份、数据和目标版本；连接或启动服务并 doctor；发送真实请求；观察响应之外的业务状态；保存响应、日志和相关副作用证据；清理本轮数据。
- **UI／E2E**：准备账号、数据和视口；启动或连接真实应用；实际操作用户路径；观察渲染、交互和业务结果；保存截图、视频、DOM／日志等原始证据；释放浏览器和本轮实例。源码或静态 DOM 不替代真实渲染证据。
- **Agent**：准备任务包、工具和输入；连接选定模型／运行时；实际执行任务；观察工具轨迹、文件／产品状态和最终结果；封存原始输出与轨迹；清理临时工作区和敏感残留。模型自述不能替代轨迹。

## 交接和验证边界

自动化设计构造或修复 Harness 时可以返回一次性结果 `verified`、`draft` 或 `blocked`：

- `verified`：已实际驱动目标路径，独立观察和证据成立，清理后仍能回读。
- `draft`：资产已形成，但至少一段尚未实际验证；必须列出恢复动作。
- `blocked`：无法安全或授权继续；必须列出原因和恢复入口。

这些交接结果不替代长期六状态。框架名称、测试文件存在、健康检查通过、页面打开、零退出码或“已完成”自述都不足以单独证明 `verified`。

## Setup 与 Loop 边界

Setup 调查、记录和回读 Harness，不因该模型自动运行产品、安装框架、创建数据、修改 CI 或生成验证器。生成或修复验证器沿 `designing-test-automation` 的既有路径，并保留授权边界。

Test Loop 先通过全局项目配置、Run 合同和冷启动盲测门禁，再只检查本轮选中的测试表面。首次适用的真实执行应同时提供 Harness 证据；不为状态标签重复同一检查。未选中的表面不阻塞本轮，缺口只阻塞依赖该表面的执行。

## 迁移规则

旧 `test-privateer-project-profile/v1` 中测试表面的 `ready` 只表示入口可定位。没有六段实际证据时迁移为 `declared_unverified`；若已知有具体缺口则使用 `partial` 或 `blocked`。不得通过配置版本升级自动获得 `verified`。
