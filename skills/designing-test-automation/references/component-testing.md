# 组件测试：检查局部交互与恢复

用于组件或页面自身的事件、反馈和状态行为。先确定真实组件及依赖替换位置；模拟服务的测试不证明真实服务协作。

## 从行为写用例

读取组件的调用方式、现有夹具和业务规则。确定初始输入、一个目标交互及可见结果；已选组件范围不强制升级为 E2E。

用真实组件发起交互。需要模拟依赖时，按实际协议准备响应的关键结构，只替换阻碍本次局部检查的边界。

按风险选择成功反馈、拒绝、等待或恢复。例如，接口拒绝后的输入保留应由可见输入值证明，不能只断言“错误组件已挂载”。

**完成条件：** 刺激、可见结果和预期来源明确，真实与模拟边界可说明。

## 编写、执行与判定

沿用组件测试框架、目录和命令；通过用户可见名称、角色或项目稳定标识操作。等待本次状态变化，不用固定休眠。

恢复用例按已确认规则继续修正和提交，核对新结果；旧提示消失本身不证明恢复成功。控制异步响应与初始状态，每例独立准备。

按授权运行目标用例。断言不符时，先核对真实组件行为和替身协议；导入、挂载或准备失败另列。可安全验证时，用已知错误响应或组件缺陷变体检查目标断言，再恢复正常输入。

**完成条件：** 失败能定位到目标行为或测试基础，未运行不写通过。

## 交付与边界

给出测试代码／设计、命令、结果及未覆盖的真实服务行为。需要真实接线证据时补集成检查，需要完整旅程时使用 writing-e2e-tests，不由局部通过推断全链路正确。

## 来源

- [Testing Library 指导原则](https://testing-library.com/docs/guiding-principles/)：通过接近用户使用方式的操作检查组件，而不是绑定内部实现。
- [Kent C. Dodds 的测试实践](https://kentcdodds.com/blog/write-tests)：真实组合与替换边界按信心需求取舍，不固定测试比例。
