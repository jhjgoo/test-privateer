# 编写单元测试

单元测试锁行为，不锁代码形状。用调用者使用的最窄稳定 seam，以最小但有区分力的例子证明一个行为。

在 TDD 中，本技能不管理 RED→GREEN；只负责选出值得实现的 RED，并证明它确实因目标行为缺失而失败。红灯不是证据，正确的失败原因才是。

## 1. 定位任务

读取调用方提供的行为依据、TCON、缺陷、代码和现有测试；项目产物存在时只作为输入。沿用项目的框架、目录、命名、fixture 和测试命令。没有代码访问权时只交付可实现的测试切片。

先分清交付范围，再判断测试目标：

- **只设计：** 交付行为、seam、oracle、最小样本和执行条件，不编写或运行；没有代码访问权时同样只交付可实现切片。
- **只编写：** 交付测试代码及运行入口，明确未运行，不为取得 RED 执行测试。
- **编写并验证：** 在获准范围运行目标测试。新行为／缺陷保护确认业务性 RED；既有行为补保护记录真实首轮结果，首次 GREEN 正常。

只授权测试时不修改生产实现。新行为首轮 GREEN 先核对行为是否已存在及断言是否有效，不伪造 RED，也不把有效 RED 当作整个开发任务完成。

**完成条件：** 已明确交付范围、测试目标、行为依据和现有测试约定；缺少命令的设计保留取证入口，不声称可运行。

## 2. 钉住 seam 与 oracle

从真实调用者使用的公开边界发起动作，通过返回值、公开状态或必要的外部动作观察结果。内部重构若会迫使测试改写，seam 选错了。边界含糊时先调查；改变生产接口超出已有授权时才询问。

每个 expected 都注明独立依据：已确认业务规则、协议、标准、worked example、人工验算常量或原理不同的参考模型。未知规则保留为待确认项，不编码成测试。既有输出只有经外部依据确认后才升级为契约。

**完成条件：** seam、观察位置、外部边界和每个 oracle 的来源均可说明。

## 3. 选最小行为切片

从已选候选测试点或 TCON 派生：

- 主行为与拒绝行为；
- 会改变结果的规则分区或决策组合；
- 合法与非法状态迁移；
- 行为拐点前、当点、后；
- 缺陷的最小稳定复现。

先实现最可能区分正确与错误的一例，再让结果决定下一例。一个用例记录来源 ID、Given、一个 When、Then 和 oracle 来源。覆盖率只用来发现遗漏，不用来制造无依据测试。

**完成条件：** 首个切片能击中一个具体规则、迁移、边界或缺陷，而非代码行。

## 4. 写清测试

保留所选 seam 上的真实符号、输入输出类型、异常、fixture、替身和运行命令；只隐藏 seam 以下、不会改变可观察行为的实现细节。

- 名称直接写“场景 → 可观察结果”。
- Arrange／Act／Assert 或 Given／When／Then 一眼可分；通常只有一个 Act。
- 多个断言可以共同证明一个行为；不相关结果拆开。
- 数据保持最小且有业务含义；同一规则的多组样本使用参数化测试。
- 关键前置条件留在测试附近；helper 只隐藏无关噪声。
- expected 使用可人工核验的值；复杂规则放进数据表，不在测试中重写生产算法。

依赖按 `真实实现 → fake → stub → interaction` 选择。只有依赖妨碍快速、确定或安全运行时才替换；只有外部动作本身是契约时才验证交互。替身保持真实协议的完整关键结构。

**完成条件：** 测试只因行为变化而失败，失败信息能指出哪个场景不成立。

## 5. 在授权范围内验证

设计或编写时先给出：行为依据、seam、oracle 来源、最小样本、目标入口及适用分支的预期结果。缺少真实 API、测试约定或命令时，只询问会改变测试的事实；不得用假设冒充项目中的可执行测试。

只设计或只编写时在相应产物处停止，明确未运行；以下只适用于编写并验证。先运行目标测试并判定结果：

- **PASS：** 调查行为已存在还是断言无效；前者可转为既有行为保护，后者修测试。不为制造 RED 改坏实现，也不声称完成了一轮 TDD。
- **ERROR：** 编译、导入、fixture、替身或环境失败；先修测试基础。
- **FAIL，但原因不符：** 测错行为、seam 或 oracle；重写 RED。
- **FAIL，原因符合：** 断言差异准确指向目标行为缺失；才是有效 RED。

有效 RED 的证据包括目标命令、退出状态、原始断言差异和重复运行结果。一次只推进一个行为；若准备数据比表达行为更重，先缩小样本、fixture 或 seam。新行为／缺陷保护分支取得有效 RED 后交回；意外 GREEN 交回核对结果及必要修正，不强制制造失败。环境受阻时交回真实缺口，不无限重试。本 Skill 不管理 GREEN／REFACTOR。

Characterization test 记录首次结果；获准且安全可逆时，在隔离副本或既有失败变体上证明其对目标行为敏感，恢复后重新运行。不为制造 RED 改坏产品代码。无法证明敏感性时，明确标记“测试可运行，回归探测能力未证实”。

测试应能单独、重复、乱序运行；项目支持时再验证并行。显式控制时钟、随机数、UUID、locale 和异步完成信号。测试资源使用隔离数据，不触达生产、真实密钥或不可逆动作。

**完成条件：** 结果符合当前分支：设计／只编写有可用产物及未执行声明；已运行有目标命令、退出状态、原始结果和真实 RED／GREEN 或受阻证据，RED 只认业务性失败。

## 6. 交付证据

最终回复给出测试文件、运行命令、结果、关联 TCON／测试点及尚需契约或集成测试覆盖的边界。调用方按当前产物契约持久化测试状态和证据。

**完成条件：** 设计或代码可追溯、oracle 独立，执行状态与证据一致；相应 TDD 分支交回有效 RED 或真实未满足原因，既有行为分支交回实际结果；没有把未运行写成通过，也没有接管 GREEN／REFACTOR。

交回调用方时附 handoff：产物位置、运行入口、实际结果或未执行声明、未覆盖边界和下一步实现／回归动作。
