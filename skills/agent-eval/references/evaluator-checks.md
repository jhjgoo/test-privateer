# 评估器与结果检查

## 测试案例有效性

- 人工或参考实现能完成任务；
- 规则与期望状态唯一或分歧已显式表达；
- 环境可初始化、隔离和重置；
- 正例通过，已知错误失败，合理替代路径不被拒绝；
- 动态依赖、时间、账户和外部数据被固定或记录；
- Agent 不能读取隐藏答案、修改评分器或污染后续运行。

## Oracle 强度

优先程序化环境状态和功能检查。轨迹用于必要顺序、安全和诊断。最终字符串只适合确有文本契约的场景。

Judge 使用前以人工标注的正例、反例、部分正确和替代路径校准，记录模型、Prompt、版本和分歧。Pairwise 判断交换候选顺序；检查长短同义答案、不同风格和不同模型来源。Judge 不稳定或未校准时只作调查线索。

## 重复与统计

一次运行只能说明一次观察。按风险决定 trial 数，报告场景数与每场景次数，不把重复运行称为独立案例。

- `pass@1`：普通单次体验；
- `pass@k`：允许多次尝试时至少一次成功；
- `pass^k`：连续 k 次都成功的可靠性。

比较版本时使用同一案例、环境和配置做配对对照。环境错误单列；样本少、差异小或 Judge 波动未校准时不宣布领先。

## Reward hacking 与评估误导

检查 Agent 是否能：读取参考答案、搜索公开补丁、修改测试或 parser、伪造中间产物、利用 Judge 指令注入、只优化可见检查而破坏组合行为。

高风险场景使用独立评估环境、提交产物重放、哈希校验和留出组合测试。公开 benchmark 只代表其任务分布、版本、harness 与预算，不能直接证明产品质量。

## 评估结论

分别报告：Agent 内容失败、环境失败、无效案例、评分器问题和未覆盖范围。聚合指标必须能下钻到案例与原始证据；关键风险不被平均分掩盖。
