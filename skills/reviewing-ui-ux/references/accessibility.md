# 无障碍

检查用户能否感知信息、理解状态并以需要的输入或辅助方式完成任务。规则检查和真实任务观察共同提供证据。

## 明确适用依据

**适用：** 感知、键盘/触控输入、导航、语义或辅助技术出现障碍，或用户要求标准符合性评估。输入包括平台、目标人群与任务、版本和状态、已有问题/记录，以及采用的标准或平台约定。

先确认标准版本、等级、适用范围与例外；没有确认依据时，可继续报告可观察的使用障碍，把标准结论留待核实。Web 内容标准、组件模式与原生平台规则具有不同范围。原生界面使用平台提供的语义与导航约定，不能直接以 DOM 或 ARIA 属性判断。

需要数值判断时，查适用条款的测量对象、单位、前提与例外，再比较实际证据。例如文本与非文本对比、目标尺寸与间距、缩放与重排各有适用条件；测试时覆盖的文字间距不等于产品默认排版要求。记录来源，不将单一阈值设为所有产品通用验收线。

依据：[WCAG](https://www.w3.org/WAI/standards-guidelines/wcag/) 用于确定采用的 Web 标准；[WCAG-EM](https://www.w3.org/WAI/test-evaluate/conformance/wcag-em/) 提供评估范围与抽样方法；[APG](https://www.w3.org/WAI/ARIA/apg/about/introduction/) 是 Web 组件设计模式，不能代替完整符合性证据。

## 组合规则检查、人工路径与辅助技术观察

**方法：** 先选任务与状态，再为不同主张选择证据。

| 问题 | 分析与观察动作 |
| --- | --- |
| 信息能否感知 | 检查必要文字和非文字信息、颜色是否为唯一线索、缩放后的内容与操作保留；需要测量时保存条件与对象 |
| 输入与导航能否完成任务 | 走完整路径，观察控件能否到达、焦点是否可见、顺序与上下文是否连贯、是否有合理退出或替代操作 |
| 语义是否表达用途和状态 | 对照视觉用途、程序语义与辅助技术实际输出，检查名称、角色、值、状态及变化通知 |
| 错误与恢复是否可理解 | 核对错误关联、修正提示、输入保留、上下文/焦点返回及恢复后的任务结果 |

规则检查前明确规则集和扫描对象，区分通过、告警、不确定、未覆盖；复核误报和适用例外。零告警只说明这次检查没有报告对应规则的问题。动态状态、复杂交互和上下文理解需用实际路径补足。

辅助技术观察保留系统、应用或浏览器、技术组合及关键配置，记录实际输出和用户动作；结构正确不保证互操作性，单一组合通过也不代表所有组合。

产出带依据的发现、覆盖状态和待确认条款。标准违反、组件约定偏离、实际任务障碍可分别成立；只确认了其中一项时按该项报告。发布整体符合声明，需要覆盖所声明范围及适用的完整页面/过程要求，抽样扫描不能越界代替。

来源：[WAI 评估工具能力边界](https://www.w3.org/WAI/test-evaluate/tools/selecting/)、[APG 示例的使用边界](https://www.w3.org/WAI/ARIA/apg/practices/read-me-first/)。
