# 交互与可用性

用用户目标、已有知识和情境解释动作；知道实现路径的评审者，要指出用户从哪里得到下一步所需的信息。以下方法按问题选用。

## 启发式评审：从界面线索提出风险

**适用：** 已有界面材料，问题仍模糊，或需要快速发现使用障碍。输入为目标任务、人群、界面及已知状态；材料未呈现的行为另列取证。

沿任务检查有作用的原则：

| 原则 | 分析动作 |
| --- | --- |
| 状态反馈与贴近用户语言 | 找出用户需要知道的状态；检查反馈何时出现、说明什么；将术语与用户知识对照 |
| 控制与退出、一致性 | 检查返回、取消、撤销的含义及后果，比较同类控件是否遵守同一约定 |
| 防错与恢复 | 找出易误操作的条件，检查约束是否适时、错误是否可理解、工作能否保留并恢复 |
| 识别与记忆、效率 | 检查用户必须记住或跨页寻找什么，首次学习与熟练操作分别分析 |
| 信息取舍与帮助 | 检查当前决策所需信息是否可见，次要内容是否掩盖动作，帮助能否回答当前困惑 |

依据产品承诺、组件约定或明确的启发式，产出“哪个对象在什么状态下，会怎样影响谁的任务”。仅有原则支持时称为风险假设，实际发生率与用户感受仍需观察。多人评审可先独立记录再合并，保留不同情境下的相反发现。

来源：[Nielsen 十项启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)、[启发式评审方法与限制](https://www.nngroup.com/articles/how-to-conduct-a-heuristic-evaluation/)。

## 认知走查：检查首次学习中的每一步

**适用：** 新用户、陌生术语、入口隐蔽或操作含义不清。先取得用户目标与知识、起始状态和可行的动作序列；路径未知时先标明待核实，不能把猜测路线当正确操作。

对关键动作回答四个问题，并引用标签、位置、图标或反馈等线索：

1. 用户此时会追求这个局部目标吗？它如何承接整体任务？
2. 用户能发现可用的动作吗？线索在哪里，是否会被遮住或忽略？
3. 用户能把动作与所需结果联系起来吗？这依赖什么知识，材料是否支持用户具有该知识？
4. 动作后，用户能识别进展吗？反馈如何说明当前状态、结果及下一步？

交付具体断点、成立的用户知识假设和需补的观察。遇到术语已为目标熟练人群接受的证据，应调整判断；不能把首次使用假设扩大到全部用户。走查支持可发现性与可理解性的推理，不替代用户成功率或满意度研究。

来源：[Wharton 等人的认知走查技术报告](https://www.colorado.edu/ics/sites/default/files/attached-files/93-07.pdf)。

## 任务可用性观察：把争议变成行为证据

**适用：** 争议在用户是否理解、何处绕路、是否省事或为何放弃。输入为研究问题、目标人群、等价起点与任务、产品版本，以及任务成功和停止的定义。

向实际或潜在用户给出业务目标，不在任务中暗示入口名或操作答案。记录选择、停顿、错误、绕路、求助、恢复和放弃；需要提示时先记录无帮助阶段，再记录提示内容与之后结果。观察和任务后主观反馈分别保存。

依据事先确定的业务结果判断完成：区分独立完成、提示后完成和未完成，并核对用户是否正确理解结果。使用耗时时说明起止点、失败与中断如何处理；比较版本时控制学习效应、任务难度和样本构成，给出不确定性。

产出所测条件下的行为分布、具体障碍和竞争解释。小样本能发现问题，不自动代表总体比例；Agent 已知控件或路径后的完成也不能证明目标用户容易发现、理解或满意。对复杂原因继续调查，避免从“没看见反馈”直接断定“实现没有反馈”。

来源：[GOV.UK 主持式可用性测试](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)。

## 状态与恢复：检查任务能否继续

**适用：** 表单、弹层、异步处理、多步骤任务及重复动作。输入包括起始状态、关键事件、产品对成功/失败的约定与已有轨迹。

选择会改变用户决策的转换：提交、等待、成功、明确失败、结果未知、取消、重试、返回。逐条检查触发条件、可操作性、反馈、输入保留、焦点/导航去向和最终业务结果；结果未知与确认失败需要不同恢复策略。复杂流程和组合由 [PPDCS](../../modeling-tests-with-ppdcs/SKILL.md) 建模，本处提供体验观察方向。

按产品和平台约定判断，交付关键转换、实际观察、未覆盖路径及最小复验。静态状态不能证明转换、反馈时机或重复动作结果。

**示意——表单反馈：** 用户改完地址后遇到保存失败。检查用户能否辨认失败、保留已填内容并回到可修正位置；重试后核对实际保存值。若只有失败截图，可判断提示表达；内容是否跨失败保留，要比较提交前后记录，不能由截图中的非空字段推出。
