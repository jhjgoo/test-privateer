# 证据策略

先明确要验证的主张，再选择现有能力能够取得的证据。能力可以来自画面观察、语义结构、操作轨迹、规则检查、测量或用户研究；工具品牌与报告版式不决定证据强度。

## 比较版本、状态与基线

**适用：** 解释视觉差异或回归报告。输入为两端版本、状态、数据、环境、基线来源及批准记录。

确认两次观察是否可比：业务状态与数据、视口、字体、语言、主题，以及影响结果的加载和动画时序。等待以目标状态可确认作为依据；为研究真实变化而设置的条件应保留，不为消除差异而抹掉它。

定位差异后分别考虑产品变化、批准的预期变化、环境变化和测量噪声，结合当前有效约定与任务影响分类。更新基线是接受特定变化的决定，要留下范围和依据；不能靠更新消除未解释问题。批准一种样式变更，也不证明所有受影响体验都已验证。

产出可复查的比较条件、差异分类、影响及补证。基线可能包含旧缺陷，差异面积和相似度都不能代替用户后果。

## 处理噪声与取证盲区

**适用：** 动态区域、字体/渲染波动、动画或测量容差干扰判断。先取得原始差异和环境条件，再定位变化来自哪里。

优先控制与研究无关的输入和时序；确需屏蔽或容差时，说明排除了什么、为何合理、会漏掉什么。关键内容被排除时，用另一种观察保留该主张的证据。不能因为反复出现就把无法解释的差异自动归为噪声。

产出处理前后仍可证明的主张和证据损失；阈值依场景验证，不把某工具默认值当质量标准。

## 多来源印证与报告解释

**适用：** 已有截图、扫描、结构或操作记录，需要判断问题及证据强度。核对每份材料的原始采集、时间、版本、状态和派生关系。

按主张交叉核对：结构能否表达用途，画面能否辨认，动作能否到达，反馈是否对应实际业务结果，目标用户能否理解。材料矛盾时保留冲突并选择能区分解释的下一观察，不按报告数量投票。

同一次采集被两个报告转述，仍是一份原始证据。独立复现需要新的操作或采集条件记录；工具未覆盖、结果不确定和已通过分别标记。来源换名或换版式时，判断依然落在内容与可比条件上。

产出“哪份材料支持哪项主张、尚不能证明什么”。额外来源只有带来不同信息才增加取证价值。

## 抽样与体验测量

**适用：** 环境组合很多、比较版本，或工具分数与真实任务表现冲突。输入为目标人群、任务阶段、指标定义、采集条件和原始分布。

按可能失效机制选择状态×数据×环境的代表组合，说明选择和未覆盖范围。组件隔离、模拟环境、真实设备和真实任务分别解释，不能以任一层替代全部。

核对测量对象、单位、统计口径、起止点、分群及样本。实验室结果与现场任务记录分开；加载速度、响应等待、布局移动和任务完成是不同主张。单次总分或平均数不能掩盖特定人群、长尾或关键步骤的失败。

等待问题同时观察触发动作、反馈出现、可继续操作及最终结果的时间线；反馈是否充分依据任务和产品承诺，原因调查需要能区分客户端、服务或其他解释的证据。相关性不自动证明根因。

产出定义清楚的所测结果与限制；用户行为、主观评价和系统性能分别解释。真实用户成功口径见 [交互与可用性](interaction-and-usability.md)，不以工具综合分数冒充完整 UX 标准。

来源：[Web Vitals 的指标范围](https://web.dev/articles/vitals)提供性能测量实例；此处吸纳指标定义、分群及现场/受控测量的区分，不绑定该指标体系或默认阈值。
