# 条目、规则与维护判据

仅在需要写条目、判断晋升或清理已有资料时读取。字段服务于追溯，沿用项目版式；一个小错误不必生成下方全部文档。

## 资料各自承担什么

| 位置 | 保留内容 | 维护方式 |
| --- | --- | --- |
| 错题本 | 失败机制、事件证据、纠正案例、未决问题、晋升指针 | 同类归并，保留事实与历史引用 |
| 项目规则 | 当前有效的条件、动作、检查方法与必要理由 | 没有特殊约定时直接写入项目根目录 AGENTS.md；已有独立规范则沿用，每项规则一个权威定义 |
| Agent 入口 | 直接承载默认规则，或指向已有独立规范与教训 | 外置资料用条件式短指针；不复制整本教训，不为内置规则新增重复文件 |
| 运行记录 | 原始输入、输出、日志与环境 | 沿用项目审计位置，条目只留必要摘要与引用 |

证据可能在 Issue、提交、测试夹具或本地记录中；注明可访问位置，去除凭证等敏感原文。维护文档不自动授权向外发消息、修产品或运行测试。用户已经授权其中的动作时沿用，无需反复确认。

规则默认落在根目录 `AGENTS.md` 的合适主题下，与已有要求合并，保留其他项目指令；文件不存在且维护已授权时可创建。教训的晋升指针指向该主题。只有项目已约定独立规范位置时才把规则写到外部文件，并在入口保留读取指引。

## 写一条能改变行动的教训

以下是结构示意，不把占位字段当作已发生事实。实际不存在的原因或验证写为未知／未运行。

```markdown
### L-<沿用编号> <具体失败机制>

适用条件与行动：<在什么条件下，应改变哪一步>
为什么：<失败如何发生；已支持机制与未知分开>
证据：<事件 ID、日期、版本、报告／提交／原始输入位置>
纠正与验证：<改动及能区分错误的检查；已运行的结果或未运行>
边界：<适用对象；应保持的邻近正常情况>
复发：<独立事件数及 ID>；审查日期：<日期，说明重复引用>
状态：<教训／规则候选／已晋升及位置／已失效及替代>
问题状态：<未修复／已止损／局部验证／目标范围已验证>
下一动作：<尚缺证据时的具体取证或检查>
```

能从条目重新定位原始事件，才能可靠去重。一个事故的三个补丁可以支持“修复遗漏相邻路径”的教训，却不是三个独立事故。没有稳定事件 ID 时，用报告、时间、版本及影响范围辨认；无法确定是否重复，先标记关联待查，不虚增次数。

“Seen”若沿用旧账本的不同审查日口径，明确它是发现日期数，另列独立事件数；规则晋升还需确认重复发现代表独立复发，或有其他充分依据。迁移统计口径时说明差异，不默默改写历史数字。

## 晋升判断

| 检查 | 可晋升的依据 | 继续留作教训的情况 |
| --- | --- | --- |
| 真实性 | 原始失败和行为路径可定位 | 只有总结、转述或无法访问的证据 |
| 复用价值 | 独立复发、共享机制或已确认的高后果约束 | 一次性操作失误、偶发环境波动 |
| 范围 | 条件与例外稳定，正常反例已考虑 | 把供应商、平台或样例局部限制扩成全局 |
| 检查动作 | 能在对应路径发现原错误 | 只有“认真检查”“提高质量”等口号 |
| 权威一致 | 与当前规范、产品决定相符，或有明确替代依据 | 冲突仍需要业务决定 |
| 落点 | 已有规范与入口可承接 | 再造一份相同规则，入口仍不可发现 |

计数门槛是筛选信号，不是自动批准器。严重数据丢失、安全或权限事件先依已确认约束处理；记录问题和规范不能代替修复。一个有影响但原因未知的事件仍有保留价值，不为了凑规则编造机制。

把教训改写成规则时，保留**条件 → 动作 → 检查**，缩去偶然的版本、账号和供应商样例值。原证据仍在教训中，规范可链接回来。需要固定数字、技术或工具时，依据应来自当前项目的有效约束，而非参考项目。

## 示例：从一次返工到规则

教学示例：写入器将坏 JSON 的解析失败转换为空列表，再写回文件，用户设置被清空。一次单测重跑通过，但没有保存原失败输入。

当前可写的教训是：“配置读失败时保留未知，停止基于该结果覆盖；收集坏文件与写入路径证据，检查已有值是否保持。”原因只在观察或复现支持范围内成立，单次通过不证明修复。

取得原始坏文件后，检查应同时行使“读取失败”“合法空列表”“用户已有设置”三种不同语义：失败时持久化值保持；合法空值按项目已确认意图处理；正常用户修改继续生效。执行未获授权或条件未齐时，这些是拟议检查。

若机制已证实且满足项目晋升标准，规范可写：“持久化写入须区分读取失败与合法空值；失败时停止覆盖。验收包括坏文件时旧值保持，以及合法空值与正常修改的行为。”将教训改为证据摘要加规范指针；发生新事故时检查遗漏入口、不可达指针或无效断言，保留未修复状态。

## 整理与失效维护

- 相同机制且同范围：合并到原编号，补事件证据与新状态，旧编号保留重定向；不同机制保留各自条目。
- 已晋升：规则正文由规范维护，教训保留历史、理由和指针；避免两个可编辑定义逐渐分歧。
- 已失效：用新版本、有效决定或验证说明原因，注明替代规则；修复一个样例不意味着整条教训失效。
- 材料读失败：保持“不可确认”，保留旧内容；不能把读取失败当没有旧规则或清空账本。
- 规则再犯：核对任务是否能读到、动作是否明确、检查是否经过错误路径，再决定改入口、规则表达或自动验证；不能断言只是 Agent 没听话。

历史审查记录注明仓库／分支、起止版本、筛选方式和已读证据。连续水位与零散覆盖分开，例如 A 已连续完成、本轮只审查 D 的一个失败：连续标记仍是 A，另列 D 的已读部分及 B、C、D 剩余缺口。重写、分支切换或多头历史无法线性表达时，按明确提交集合记录，不伪造连续区间。

已有独立规范时的入口示意：

```markdown
修改配置写入路径时，读取 docs/code-standards.md 的“配置写入”与 LESSONS.md 的相关教训；审查时核对所列失败与正常边界。
```

按真实任务选择触发条件和相对路径；复制到嵌套目录时核对解析位置。文档指针依赖宿主读取与调用，不能宣称其存在就保证执行。
