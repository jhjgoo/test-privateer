# 评估 Prompt

评估 Prompt 是否让目标模型在当前宿主和任务中稳定表现出目标行为。交付审查、最小修正和验证证据；不因文字看起来专业就判好，也不因模型、宿主或版本变化就机械重写。

## 1. 固定评估对象

明确目标模型、宿主、任务、使用者、期望行为、允许自由度和真实边界。模型或宿主未知时仍可审查业务契约和内部冲突，但模型适配保持未验证。

盘点实际进入模型的 Prompt 表面：消息角色与协议层级、System／Developer 稳定指令、Skill／规则文件、工具描述、请求模板、动态任务输入、历史与工具结果、示例、运行配置及会改变优先级的宿主指令。只读取当前任务可访问的部分；缺失内容说明影响，不假定单个文件就是完整 Prompt，也不把 Markdown 标题或 XML 标签当作协议权限。

**完成条件：** 能指出评估针对哪个模型、宿主、任务与 Prompt 组合，以及本轮要改善或保护的具体行为。

## 2. 建立行为依据

优先使用真实失败、运行记录、用户反馈和已确认规则。区分：

- 产品、安全、权限和输出契约；
- 宿主、工具、模型和运行配置事实；
- 有历史失败依据的行为规则；
- 经验性建议和仍待验证的模型假设。

只有写法会改变行为、正确性、权限或可验证性时才形成 finding。篇幅、语气和格式偏好本身不构成问题。

**完成条件：** 每项评估标准都有来源；未知没有被升级为目标行为。

## 3. 审查 Prompt

检查目标、上下文、权限、决策条件、完成标准和输出要求是否在实际使用位置清楚一致。按“最小充分”审查输入：保留承担判断条件的规则、事实、来源、对象关联和例外，删除不影响当前决定的噪声；不能为缩短文本或提高缓存复用而删除判断依据。结构化输出要求只约束格式，业务事实、引用和确定性计算需由可观察的程序校验承接。

需要模式卡时读取 `references/prompt-review-patterns.md`，按当前任务选择相关项，不逐项套用。涉及缓存、成本或延迟时，把质量、输出、Token、命中、账单和延迟分开取证；缓存命中不证明正确性，也没有实际用量时不推断收益。

逐项核对比较性主张：“提高、下降、更准”等结论必须有该指标同口径的调整前、后证据。只有新版达标数据时，只报告本轮达标情况；其他指标的基线不能替代它，也不能在建议改写结论时补出“有所改善”。

重点寻找：指令冲突、有效规则放错层级、同一含义重复加权、判断工作被写成固定步骤、示例过度限定、宿主事实失真，以及“做了动作”被写成“结果已成立”。

沟通质量 findings 可用四维失败标签定位：**数量**（遗漏完成任务所需条件，或无关背景过量并影响行为）、**质量**（主张超出证据或把模型自述当结果）、**关系**（偏离目标、错误路由、越权或响应不可信外部指令）、**方式**（对象、动作、顺序、边界或判定不清，导致无法执行／复跑／核验）。逐项记录证据和行为影响，保留维度冲突与未知；不做四维平均分或总分。

目标模型发生变化时，重新核对官方资料或该模型的行为证据；迁移只是目标配置变化，不另建一套评估流程。相邻模型或其他厂商的经验只能生成待验证假设。

**完成条件：** 每个 finding 指向具体位置、行为影响和直接证据，且没有把一般写作偏好包装成缺陷。

## 4. 提出最小修正

每项修正说明：要解决的失败、修改位置、预期改变、可能伤害的正常场景和验证方式。优先调整最接近行为决策的位置；能删除冲突或重复就不再叠加更强措辞。

用户只要求审查时给候选差异，不改文件。用户要求修改时，在授权范围内更新 Prompt 和相关引用；不能修改宿主或工具配置时说明边界。

**完成条件：** 候选差异只包含有证据支持的改动；允许结论为“保留当前 Prompt”或“证据不足”。

## 5. 验证行为

至少设计目标失败场景、邻近正常场景和必要边界场景。优化效果以调整前版本为基线、调整后版本为候选，按同一冻结案例逐例配对；固定模型及可确认版本、宿主、材料、工具、初始状态、权限、推理配置、预算、尝试数与判据。实际执行已有授权与条件时才运行，否则交付可执行设计。

采用执行与评审两侧盲化：独立执行会话只见本组指令与任务，不见新旧标签、另一版本、隐藏判据或历史答案；独立评审者只见匿名输出、必要证据和冻结判据，不见版本映射、修改意图或预期赢家。随机化呈现顺序，映射由编排者单独保管，评分锁定后才揭盲。被测指令本身无法隐藏；记录路径、轨迹或输出造成的泄漏，未做到的盲化不称为双盲。

记录 Prompt、Schema、工具和业务规则版本及回滚条件。判断实际结果和产物，不按关键词、固定标题、Schema 通过、模型自称遵守或单次偶然通过评分。生成式行为按风险决定是否重复；环境、工具和评分器问题与 Prompt 失败分开记录。

量化时预先约定指标、分母和通过阈值，报告逐例配对结果、目标改善、邻近退化、有效样本数和缺失／错误项；样本不足时只作方向性结论。两版都通过不证明提升；声称 Skill 本身有贡献时另设无 Skill 基线，它不能替代旧版基线。

框架默认沿用客户现有测试入口；没有框架时也能交付上述设计或执行已授权的原入口对照。客户选择进一步量化、对象为 Skill 或指令包，且能忠实保留目标运行语义时，可选 SkillEvaluator，读取 `references/skillevaluator-integration.md` 并交由官方 `skillevaluator` Skill 执行。不默认安装或运行，也不为使用框架而改变普通 Prompt 的消息角色、工具或加载方式。

**完成条件：** 结论能说明目标问题是否改善、正常场景是否退化、盲化实际范围和证据适用配置；未实际对照时不声称优化有效，未选框架不阻断审查。

## 交付

```markdown
## 目标行为与配置
模型 — 宿主 — 任务 — Prompt 表面 — 边界

## 发现
位置 — 行为问题 — 直接证据 — 影响

## 最小修正
候选差异 — 预期改善 — 副作用风险

## 验证
失败与邻近场景 — 旧版／新版及冻结配置 — 盲化与揭盲记录 — 框架选择 — 指标／有效样本／错误 — 配对结果或待执行条件

## 结论
保留／建议修改／证据不足 — 适用范围 — 下一步
```

若问题属于完整 Agent 的工具、环境、编排或产品结果，交给 `agent-eval`；仅把已经定位到 Prompt 表面的部分留在本 Skill。

**完成条件：** Prompt 结论有目标模型与行为证据，修正范围最小，验证包含目标与邻近场景，且没有把 Prompt 质量等同于完整 Agent 质量。
