# 可选 SkillEvaluator 量化评测

客户已选择 SkillEvaluator 且需要执行或准备量化评测时读取。`prompt-eval` 负责目标、案例、判据和结论边界；官方 `skillevaluator` Skill 负责工具操作，不复制它的 CLI 教程。

## 适用对象与选择

- 对象为 Skill 或指令包，且能证明框架保留目标环境的实际消息角色、加载方式、工具、权限及任务输入时，可评估旧版和新版完整快照。原本就是 Skill 也要核对；不等价时只能评价该评测宿主，不能外推为生产效果。
- 普通 System Prompt、API 请求模板或工具描述若必须改变协议层级或运行方式才能包装成 Skill，继续用原宿主／现有 harness 做配对评测。框架支持读取文件不代表测试对象等价。
- 客户未选择、只要定性审查或已有合适框架时，保留原入口。SkillEvaluator 不是使用 `prompt-eval` 的必装依赖。

## 官方入口与就绪

官方来源：[NVIDIA/SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator)，操作入口为该仓库 `skills/skillevaluator/SKILL.md`。

选用后先读取宿主中的官方 Skill，核实 CLI 版本与对应命令；缺失时说明来源、安装位置和缺项，按客户授权安装，安装后重新读取。选中框架不自动授权安装依赖、调用付费模型或上传数据；已有明确授权则直接复用。

执行前确认经审阅的数据集、Agent／Judge 模型、凭据、沙箱、尝试数及预算。密钥只由环境提供，原始材料遵循客户数据边界。缺少条件时交付可执行计划与阻塞项，不生成假分数。不要把维护本仓库的 policy、固定 CLI、模型矩阵、网关或密钥配置复制到客户项目。

## 运行与解释

1. Tier 1 静态检查只说明结构等静态问题；行为效果使用 Tier 3 的实际结果。
2. 旧版与新版分别运行同一冻结数据集和配置；按主 Skill 的盲化约定检查真实候选输入、Judge 输入和轨迹，不能因框架存在 A/B 或 compare 功能就宣称双盲。
3. 官方带 Skill／无 Skill 比较测的是 Skill 贡献；旧版／新版比较才回答这次调整是否改善。需要贡献主张才补无 Skill 组，不用 Skill Lift 替代版本差异。
4. 核验目标 Skill 的实际读取，分开报告输出质量、加载状态与运行完整性。按案例对照目标指标和邻近退化，关键结果或安全失败不能被平均分、退出码或总体 PASS 抵消；评分器用独立正反例校准。
5. 保留原始报告、配置、快照哈希和失败记录。未评分不当作零分，也不从分母中悄悄删掉；工具错误与内容失败分别报告。仅可比较同条件结果，两版都通过时说明未观察到提升。

交付框架／版本、实际运行范围、逐例结果、盲化限制及报告位置。只完成设计、静态检查或接线冒烟时，分别标注，不升级为量化效果已验证。
