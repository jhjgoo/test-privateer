# Prompt 审查模式

只在相应现象影响本轮目标行为时使用。模式用于生问和定位，不直接构成 finding。

## 契约缺口

- 目标行为无法观察，只有“高质量、专业、全面”等形容词；
- 缺少受众、材料来源、适用范围、权限或完成标准；
- 未知事实被要求补全，或推断被允许充当规则；
- 输出格式与实际消费者、解析器或评审动作不匹配。

## 指令关系

- System、Skill、工具描述和用户请求对同一行为要求相反；
- 关键规则只存在于不会被读取的分支或参考文件；
- 同一规则散落多处且含义漂移；
- 示例、默认值或历史实现暗中覆盖当前规则；
- 提醒频率和强调程度让次要规则压过任务目标。

## 自由度错配

- 开放判断被固定成唯一步骤或工具顺序；
- 权限、财务、安全或破坏性操作只给抽象原则；
- 为修一个案例增加全局禁令，使邻近正常任务受阻；
- 以输出措辞、关键词或标题代替行为和结果；
- 用一个黄金示例锁死语气、长度或方案。

## 证据错配

- 调用工具、读取文件或写出计划被称为完成；
- 计划命令、预期结果或模型自述被写成执行证据；
- 一个样例、一次运行或相邻模型经验被外推为稳定行为；
- 环境失败、工具错误和内容失败没有分开；
- Judge 分数没有人工校准、正反例或适用范围。

## 模型与宿主适配

先核对目标模型和宿主的当前官方契约及实际行为。重点检查：

- 宿主是否注入其他规则、工具列表或批准边界；
- Prompt 是否依赖目标模型不支持的参数、输出或工具机制；
- 为旧行为添加的补丁在当前配置下是否仍解决可复现问题；
- 当前模型的主动性、格式、验证或澄清倾向是否与业务目标冲突。

模型变化时复用同一行为样例和评估标准；旧 Prompt 是基线，不是必须保留的结构。

## 最小修正准则

1. 先补缺失的事实与完成标准。
2. 再修冲突和错误位置。
3. 再删除漂移、重复和无依据补丁。
4. 最后才增加新指令或示例。

每个修正都要能回答：哪条行为证据会证明它有用，哪条邻近场景会证明它没有过度生效。
