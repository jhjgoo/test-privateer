# 引导词卡

引导词是注意力触发器。用它碰撞当前对象，产生候选问题；不逐项填写，不逐项询问。

## 选择层

| 当前缺口 | 使用 |
| --- | --- |
| 测试使命、信息源、资源、边界或交付不清 | Mission／CIDTESTD |
| 产品组成、业务链、系统关系或数据流不清 | 交给 SFDIPOT 扫描；本轮只问会改变扫描边界的问题 |
| 谁在意、什么算好坏或凭什么判断不清 | 询问利益相关者、价值、场景和 oracle 来源 |
| 已知要查什么但不知道怎样取得证据 | 停止澄清，交给测试实验设计 |

## Mission／CIDTESTD

| 引导词 | 寻找的信息 |
| --- | --- |
| Mission | 根据用户当前动词，测试要帮助测试人员学到什么；普通测试分析不追问研发、联调或上线决策 |
| Customer | 谁使用、受益、继续处理结果或承受错误 |
| Information | 可用的真实样本、历史数据、日志、人员和同类产品 |
| Developer Relationship | 谁清楚实现、变化、脆弱区域和可观测性 |
| Test Team | 测试人员掌握的历史、经验、现象和现有证据 |
| Equipment & Tools | 可用环境、账号、数据、日志、工具和控制能力 |
| Schedule | 构建、反馈和执行窗口怎样影响本轮深度 |
| Test Items | 改了什么、影响什么、不测什么、依赖什么 |
| Deliverables | 从用户当前动词推断候选测试点、测试设计、执行协助或证据说明；语义不清才追问 |

## 问题动作

- **主张：** 当前要确认什么结果，理由是什么？
- **假设：** 哪个前提不成立会改变结论？
- **替代解释：** 什么其他情况也会产生这个结果，怎样区分？
- **复盘：** 请按最近一次真实经历从开始到结束走一遍。
- **举例：** 最近一次发生是什么情况？
- **反例：** 什么看似相同却必须区别处理？
- **边界：** 从哪里开始，什么时候结束？
- **差异：** 角色、企业、渠道、状态或时间变化后有什么不同？
- **证据：** 从什么数据、日志、单据、系统或人员处验证？样本、时间窗和观察方式支持多大范围的结论？
- **后果：** 系统没有报错时，业务结果仍可能怎样失败？
- **恢复：** 部分成功、失败或中断后，谁发现、谁接手、怎样恢复？

每个候选问题按“是否清楚／依据是什么／改变什么”过滤：是否单一清楚；是否查事实、证据或可推翻假设；答案会改变哪项测试工作。先用可取得材料回答，只将需要用户判断且会改变当前测试的问题交给用户。
