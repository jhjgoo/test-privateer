按 artifact-routing 定位同前缀的分析和可选依据文件。开始设计才创建本文件；编号按 artifact-routing，保留既有权威用例ID。以当前规则为准，过期用例标记需重设计或退出范围，原始执行结果不得覆盖。

# <需求标识与短名> — 测试用例

## 本轮重点
设计交付先说明重点验证什么、为何优先及准备缺口；汇总执行结果时，改用 artifact-routing 的“测试报告的阅读顺序”，先给当前结论、影响结论的未决项和下一步。没有执行记录时保持设计状态。

## 范围与依据
链接测试分析、所选测试点和规则。说明本轮覆盖、尚未设计与排除部分。设计完成、执行条件和实际结果分别说明。

## 数据与执行准备
仅记录必要的账号、数据、依赖、操作与观察入口。夹具独立，别名不冒充已有资源。版本与环境未调查标待核实。

## 用例与探索任务
按业务分组，沿用 designing-test-experiments 的交付要求。批量用例提供便于选择工作的表格或索引，已有覆盖表能承担该作用时复用；单条用例可直接给完整详情。每条保留编号、前置、动作、预期及来源、最小证据、关联测试点／风险和当前安排。

共用准备在前文定义，长步骤和多分支预期按 ID 展开；短步骤和短预期可直接放进表格。探索章程写目标、动作范围、观察和转向信号，不以未知规则判通过或失败。业务目标与精确操作并存，具体用词按 artifact-routing 的“面向读者的测试表达”。流程／时序／状态图仅辅助解释切点，测试点脑图留在分析文档，图与表不另建两套预期。导出 XMind 时，源稿不是完整 Case 表就按原 ID 汇集准备与详情为临时转换输入，再按导出 Skill 核对字段完整性；不以摘要导出冒充完整用例。
