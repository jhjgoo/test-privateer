# 编写接口测试

从真实请求检查接口承诺。响应正确与业务完成分别取证；按目标选择真实依赖，不因使用 HTTP 就宣称完成集成或 E2E。

## 1. 定位任务

读取相关需求、测试条件、缺陷、API 合同及现有测试。核实服务地址、身份取得方式、数据准备入口、框架、目录和目标命令。已有事实直接沿用，不要求先生成策略报告。

- **只设计：** 交付请求、前置、观察与独立预期，不安装或执行。
- **只编写：** 交付代码与运行条件，明确未运行。
- **编写并验证：** 沿用项目工具，运行目标保护；仅缺少源码不阻止条件已具备的黑盒测试。

区分新行为／缺陷保护与既有行为补保护。用户只授权测试时，不修改生产实现。未知事实只阻塞依赖它的动作。

**完成条件：** 目标行为、执行许可、调用合同及影响实施的缺口明确。

## 2. 固定请求与判定依据

每例写清身份、资源归属、初始状态、请求和结果观察入口。每个精确预期来自已确认规则或协议；当前响应只能作为观察，不能自行升级为合同。

公开接口契约中的状态码与请求／响应字段保持精确。内部字段和实现组件不作为接口步骤或 oracle；有明确控制或观察入口时放在数据准备或技术依据中。没有入口时标出缺口或改派测试层级。

按目标分别断言响应与业务效果：重读写入、核对状态，或观察承诺的下游动作。返回成功或符合 schema 不能代替这些结果。读接口只验证其承诺，不虚构副作用。

需要真实数据库、消息或消费者／提供者证据时，按需读取[集成与契约](../designing-test-automation/references/integration-contract-testing.md)。替换了目标依赖，就保留真实边界未验证的限制。

**完成条件：** 请求可发起、结果可观察，每个 expected 都有独立来源。

## 3. 选首个有区分力的用例

从已选风险中挑一例，说明它能发现什么错误。成功、拒绝、边界和状态迁移按当前规则展开，不把所有方法变成必做清单。

| 目标 | 用例安排 |
| --- | --- |
| 写入或状态改变 | 准备有效状态，发起请求，再独立读取承诺的结果 |
| 对象／操作权限 | 仅引入目标权限差异，其余前置有效；检查拒绝及受保护状态 |
| 幂等 | 规则明确后才断言重复请求结果和副作用次数 |
| 并发 | 构造可控竞争或交错，核对最终状态；串行重复不能代替 |
| 异步 | 用本次相关标识等待完成信号；等待预算注明依据 |

权限反例若被参数错误或认证失败提前挡住，不能证明目标授权正确。未知幂等语义、响应码或业务时限保留为缺口。

**完成条件：** 目标错误会使某个业务断言失败，而不是只让测试无法启动。

## 4. 编写并隔离数据

沿用现有框架、HTTP 客户端、目录和命令。缺少框架时选项目内最小方案，纯接口不引入浏览器。

名称写“场景 → 结果”。准备、请求、观察和清理在代码中可辨认；多次读取可以共同证明一个行为。关键身份、输入和预期留在用例附近，helper 只隐藏无关重复。

每例可独立准备，资源标识关联本轮。账号与密钥从获准配置读取，不写进代码或报告。取得可用资源标识后安排失败路径清理；先保存必要证据，只清理本轮拥有的数据。清理错误单独保留，不能覆盖原业务失败。

**完成条件：** 用例不依赖前例残留，准备和观察来自已核实入口，失败后仍能定位本轮资源。

## 5. 执行与核实判错能力

按授权运行目标测试，再选择相关回归。记录首次结果，分别处理：

- **通过：** 既有行为首次通过正常，不伪称完成 TDD。
- **业务断言不符：** 保留脱敏请求、响应与状态差异，核对前置和预期；不修改 expected 迎合实现。
- **准备或工具失败：** 说明哪些断言未到达；启动、数据或认证准备错误不是目标缺陷的有效 RED。
- **重跑后通过：** 保留首次失败，区分业务重试、异步轮询与套件重跑。

缺陷保护能在未修复版本复现时，保存指向目标缺陷的失败。既有行为可在安全夹具用已知失败变体验证，再恢复并复跑。仅改错 expected 只能检查断言接线，不能证明能发现业务缺陷。没有安全验证条件时，明确判错能力未证实。

**完成条件：** 结果关联本轮命令和版本，业务失败与环境、清理问题分开；没有以旧报告或未运行的代码声称通过。

## 6. 交付

沿用[共享表达](../test-privateer/references/artifact-routing.md#面向读者的测试表达)，先说本轮完成与缺口，再给测试文件、命令、预期来源、实际边界、首次及重跑结果、数据清理和下一动作。只设计或只编写时交付相应产物。

有调用方时交回现有执行／报告流程，不为交接重复运行。**完成条件：** 接手者能找到测试、运行条件及证据，知道还缺什么；结论不超过实际观察。

## 方法依据

- [OWASP 对象级授权](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/)：登录成功不能代替对象权限；本 Skill 不是完整安全测试指南。
- [AWS 幂等 API](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)：重复请求结合业务语义，不套用固定 token 方案。
- [Pact 契约与功能测试](https://docs.pact.io/consumer/contract_tests_not_functional_tests)：消息兼容与业务效果分别取证。
