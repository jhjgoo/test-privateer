# 需求测试分析模板

使用 artifact-routing 确定名称和位置。主分析独立回答测什么、为什么及下一步；详细依据链接到来源或按需拆分的 basis，用例另存。按业务组织全部已识别测试点，不按工具强制分章。不填空章节，不承诺穷尽测试空间。

## 完整测试点清单
复杂范围先用 Mermaid mindmap 概览业务层级和测试方向，再按业务分组提供全部已识别测试点的精简表格。脑图节点保持简短，名称或 ID 与明细一致；图不重复维护风险状态或执行结果。脑图过大时按业务拆分，不把完整用例塞进图中。

共同依据、方法、安排和理由在分组开头说明，个别差异在对应行补充。每行是可继续设计的具体行为，不能只写“权限测试”等类别；无需为正常行为硬编风险。

采用普通 Markdown 标题与表格，不使用 HTML 折叠。阅读器不支持脑图时用概览短表；测试点明细仍用分组表格，不退回重复长列表。业务流程或关键先后关系确有必要时另用 Mermaid 流程／时序图，图不代替精确规则。

## 交付前核对（不复制为报告章节）

复杂范围有可读的脑图概览，测试点按业务分组，关键先后关系已表达清楚；精确规则继续使用决策表。阅读器限制导致采用替代形式时说明原因，不能仅为减少图表重复而省略必要概览。逐项对照规则、模型和测试预期，动作与结果措辞一致。行动清单突出当前需要用户决定或可继续开展的工作；不以图的数量或链接存在代替内容检查。
