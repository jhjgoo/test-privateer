# 按需接入官方 e2e

只在已选中 tester-army 的 e2e 框架时读取。本文件负责接入边界，具体 API 以项目版本配套的官方 Skill 为准。

## 先核对项目

1. 读取项目规则、包管理器、锁文件、现有测试和启动命令。已有合适框架就回到该框架，不另装 e2e。
2. 核实当前授权覆盖安装、服务、测试数据与外部调用。仅超出范围才询问；项目内正常步骤连续推进。
3. 核实所选版本的 Node、浏览器及宿主要求。环境不符时说明缺口，不升级全局运行时或改无关配置。

## 获取配套能力

已有安装时，先读项目中的官方 Skill、安装包文档或该版本的 `e2e guide`。记录框架版本和 Skill 来源；无法证明相匹配时先核对，不混用旧包与最新 main 指令。

新接入先按[官方接入说明](https://e2e.tester.army/docs/coding-agents)及所选版本帮助检查初始化的文件影响，再在项目配置。当前文档提供 `e2e init`、包内 guide 和单独获取 Skill 的方式；使用项目包管理器，锁定实际依赖版本。

只取得当前任务需要的官方 e2e Skill，不批量安装其他 Skill，不维护伪称官方的改写副本。已有自定义 Skill、MCP 配置和锁文件约定不得覆盖。宿主不自动注册 MCP 时按其支持方式处理；CLI 能运行不代表 MCP 已接入。

## 建立首条业务保护

1. 读取配套 Skill 的完整主文件及当前任务所需参考，再写配置和测试。
2. 先运行确定性业务操作与精确断言；不因框架支持 AI 就强制配置模型。
3. 需要 AI 时，每次操作表达一个目标，随后断言实际业务结果。按官方要求安全提供凭证，不将密钥写入测试、目标文字或报告。
4. 用该版本的禁用缓存选项验证真实模型行为。缓存回放成功与模型冷运行分别取证，不手改缓存伪造成功。

只打开首页不等于完成业务用例。断言和数据隔离沿用方法设计；在受控夹具中验证错误路径能被发现，恢复后复跑。

## 保留本轮证据

分别核对配置成功、测试启动、业务断言到达三个状态。配置能加载不等于测试已经执行，服务启动也不等于断言通过。

记录命令、依赖与模型配置标识、运行时间／身份、测试文件、结果和证据路径。遵循安装版本的报告说明，区分配置失败、测试失败及模型／环境故障；读取报告前核对它属于本轮。

保留首次失败、重试、跳过与阻塞。先看失败步骤和必要诊断，不把整份大型 AI trace 或含敏感数据的视频默认送入上下文。初始化、编写完成、实际运行分别记录。

结束时只停止本次服务，清理本次拥有的数据。缺少网络、浏览器、凭证或配套资料时交回具体失败环节及下一动作，不声称已接入。

## 官方依据

- [接入与 Skill](https://e2e.tester.army/docs/coding-agents)：获取和运行入口。
- [快速开始](https://e2e.tester.army/docs/quickstart)：按所选版本核对依赖；无模型测试与 AI 步骤分别准备。
- [缓存](https://e2e.tester.army/docs/caching)：区分冷运行与回放。

这些是查证入口，不是永久版本保证；已验证的版本与命令留在项目运行记录。
