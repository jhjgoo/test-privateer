# 测试轮次记录模板

测试轮次记录是跨阶段工作的唯一状态索引。它只保存状态和指针，不复制 TCO、需求分析、测试依据、用例、原始证据或信心报告正文。

默认位置：`testing/runs/<run-id>/run.md`

Run ID：`RUN-<YYYYMMDD>-<NNN>`。序号按当前项目和日期递增；创建后保持稳定。

轮次状态、测试判定和测试信心分开维护：

- 轮次状态描述流程是否仍需推进；已完成不表示测试通过。
- 测试判定留在对应执行记录，使用通过、失败、跳过、受阻或待判定。
- 测试信心留在 `assessing-test-confidence` 生成的报告。

旧轮次记录若混入单项测试判定，恢复时把判定移回执行记录；本节只保留已完成／未完成范围、流程状态和指针。

## 盲测 wave 索引

| Wave ID | 子代理会话／任务 ID | 模型／宿主 | 质量视角 | 稳定操作基线／项目输入 | 明确未披露的开发材料 | 任务包哈希 | 覆盖指纹 | 隔离输出／证据指针 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

这里只保存可审计边界和指针，不复制盲测 prompt、原始输出或证据正文。盲测结果封存后再记录知情回归的输入和结果；同一子代理上下文不得同时充当两个独立视角。

稳定操作基线可包含宿主固定规则、全局 RTK、全局／项目级 Skill、项目规则、项目测试配置和获准 CLI；它们不因自动注入、全局安装或父级继承而构成开发上下文污染。记录可观察到的名称、来源、版本或哈希即可，不复制完整系统提示词。

开发聊天、实现理由、修复假设、diff、开发自测、既有 Finding 结果、预期缺陷、rubric 和携带这些内容的记忆必须隔离。发现未预先列出的稳定操作基线时补记并检查其内容；只有包含任务特定开发材料且无法剥离或审计时，该 wave 才无效或记为 `BLOCKED`。

知情回归交接必须引用本文件的 Run ID、封存 Wave ID、目标版本和封存证据哈希／指针。新会话不创建新 Run ID；知情回归子代理只返回隔离 handoff，由本轮合成者更新共享资产。

覆盖指纹使用“测试表面 + 身份／数据／初始状态 + 动作／路径 + Oracle + 故障或质量视角”。相同指纹复验时补充目的：修复回归／稳定性调查／环境恢复／版本对照；没有目的则跳过。

宿主无法创建或审计独立子代理时，在状态中记录 `BLOCKED`。用户显式接受降级后，记录授权和原因，并在最终报告保留“独立盲测未完成”。
