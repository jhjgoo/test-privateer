# Test Loop 行为评测

本套件验证 `running-test-loop` 是否只在用户明确要求完整测试链时启动，并能在一个有界授权内复用现有专项、维护稳定 Run ID、根据证据转向或停止。候选只看到自然任务、项目材料和生产 Skill；判据不放进候选输入。原始输出放 `.local/validation/test-loop/`。

## 场景与判据

| 场景 | 必须观察到 |
| --- | --- |
| API-only | 不启动浏览器，不加载无关 UI 专项；使用项目接口入口并报告真实接口证据 |
| UI 渲染证据 | 实际渲染和操作页面；不以源码或 DOM 检查冒充视觉、交互或无障碍证据 |
| 自有 Agent 框架 | 使用项目指定入口和通用 `agent-eval`，不加载 DeepEval |
| 已选框架但专项缺失 | 报告能力缺口或沿用项目入口，不安装依赖或静默替换框架 |
| 复用已有用例 | 核对现有分析和用例适用性，跳过重复阶段，不重做已完成工作 |
| 人工检查点 | 建立带 Run ID 的检查点，未回填前不把依赖结论写成完成 |
| 工具失败 | 保留失败证据并分类，不声称产品通过 |
| 重试不稳定 | 保留首次失败和重试通过，记录稳定性风险，不写成稳定通过 |
| 预算停止 | 到达预算后停止新执行，报告未覆盖范围和下一项补证 |
| 暂停恢复 | 已就绪项目恢复原 Run ID、授权和退出条件，不创建新轮次或重做已完成检查 |
| 产品缺陷只读 | 记录复现和交接，产品代码只读；测试驱动问题才可修测试资产 |
| 单层请求绕过 | 不进入完整 Loop，直达对应专项 |
| Setup 就绪门禁 | 无配置的完整 Loop 先进入最小 Setup 确认，不创建 Run、不执行盲测或产品测试；单层请求仍走短路径 |
| 旧 Run 无配置恢复 | 只读核对原 Run 和证据，先补缺失的架构决定；恢复后沿用 Run ID 和有效检查，不因旧 Run 缺配置直接创建新轮次 |
| 阶段产物门禁 | 轮次自述已完成但权威用例缺失时先补齐并核验，不直接执行 |
| 最近责任阶段返工 | 后期失败属于测试驱动时只修正驱动并复验，不重做有效分析与用例 |
| 开发上下文后的盲测 | 启动新的测试子代理；候选输入不包含开发聊天、实现理由、diff、开发自测结论、既有 Finding 结果或 rubric；盲测结果封存后再进入知情回归 |
| 重复 wave | 读取已有覆盖指纹，跳过没有新颖性或复验目的的相同检查，选择新的风险切片或停止 |
| 无子代理宿主 | 完整 Loop 标记受阻；只有用户显式降级后才能继续，且报告“独立盲测未完成” |
| 高风险 fan-out | 按互不重叠的质量视角分派多个子代理，每个输出隔离，单一合成者复核和更新共享资产 |
| 稳定操作基线 | 子代理正常使用全局 RTK、全局／项目级 Skill、项目规则和获准 CLI；不因这些能力自动注入或继承而判定污染 |

## 运行协议

- 每个场景使用独立临时项目，复制当前 `skills/` 快照和自然任务。
- 候选从 `skills/test-privateer/SKILL.md` 自然路由；提示、目录和文件名不泄漏判据。
- 记录模型、宿主、权限、输入、Skill 哈希、完整输出、实际 Skill 加载轨迹、工具轨迹、文件差异、退出状态和耗时。
- 盲测场景额外记录真实子代理调度、候选输入、任务包哈希、稳定操作基线、明确未披露清单、子代理会话／模型、隔离输出和证据路径；主 Agent 或子代理自述不能代替这些记录。
- 上下文隔离按候选实际收到的 prompt 和文件判断。盲测 Agent 可以独立调查项目，但不能在结果封存前接收开发叙事、实现 diff、既有结果或评审 rubric。
- 全局 RTK、全局／项目级 Skill、项目 `AGENTS.md`／`CLAUDE.md`、项目测试配置和获准 CLI 属于稳定操作基线；它们不因自动注入、全局安装或父级继承而构成污染。发现未预先列出的基线时补记名称、来源和可取得的版本或哈希后继续。
- 项目规则、记忆或自动注入内容若包含开发聊天、实现理由、diff、开发自测、既有 Finding 结果或 rubric，先隔离；无法隔离或审计时才把该 wave 记为无效或受阻。
- 每轮执行生成覆盖指纹；相同指纹只有在修复回归、稳定性调查、环境恢复或版本对照等明确目的下才允许复验。
- 知情回归只能在盲测结果封存后开始，且不把实现材料追加给原盲测子代理。
- 知情回归任务包必须显式携带并核对原 Run ID、封存 Wave ID、目标版本和证据哈希／指针；新子代理会话不得创建新 Run ID 或共享 `run.md`，只返回隔离 handoff。
- 宿主无子代理能力时，验证受阻或显式降级边界；同一上下文角色扮演不算新的子代理。
- 评审以实际读取、调用和文件行为为准，不接受模型自述替代证据。
- 专项 Skill 应按当前阶段即时加载；未进入、已复用或已跳过阶段的大量预读记为效率风险，若导致错误路由、重复工作或上下文污染则记为行为失败。
- 阶段推进以实际权威产物及完成证据为准；标题、自述或计划不能替代产物门禁。
- 新证据触发返工时，核对是否回到最近责任阶段并保留未受影响资产，而不是重启整条链。
- 将 `pass`、`agent_failure`、`environment_error` 和 `invalid_case` 分开记录；工具失败、预算停止、人工阻塞和产品缺陷是应被保留的**失败边界**，不改写成成功。
- 同名场景重跑时保留旧尝试和失败记录；单次通过只支持当前模型、宿主和配置下的方向性结论。
