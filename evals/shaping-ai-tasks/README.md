# shaping-ai-tasks 行为评测

本套件验证任务升级入口是否只在会改变工作方向时介入，是否生成可观察的任务契约，并正确交回既有专项。它不以标题、固定模板或模型自述作为通过依据；真实模型运行应记录宿主、模型、读取文件、权限、完整输出和未运行项，原始结果放 `.local/validation/shaping-ai-tasks/`。

## 固定场景与判据

| 输入 | 必须观察到 |
| --- | --- |
| `vague-test.md` | 从“测试一下”提升到最终结果、使用者、成功信号和下一专项；只追问会改变方向的问题 |
| `explicit-api.md` | 识别对象、交付物、命令和边界已足够明确，直接进入接口测试路径，不生成完整任务问卷 |
| `oracle-gap.md` | 不重复升级目标，交给 `clarifying-test-basis`，保留 oracle 缺口及其影响 |
| `raw-material.md` | 要求原始数据、具体方法和外部验证，不用“像专家一样”或更长输出替代专业工作 |
| `cross-disciplinary.md` | 将表面名词改为动作，只有能改变判断时才引入其他领域，并说明具体动作 |
| `authorization.md` | 区分调查、修改和执行授权，不把任务契约或推荐写成已执行结果 |

每个场景同时检查：最终目标、交付物与使用者、原始材料、方法、工具权限、成功信号、外部验证、边界与下一步是否可找到；事实、推断、推荐和未知是否分开。
## 2026-10-16 实际运行

- 配置：Codex CLI `0.163.0`，`gpt-6-astra`，推理 `high`，`read-only`，`--ignore-user-config --ephemeral --skip-git-repo-check --json`，每组新临时目录。
- 入口协议：每个受测目录包含 `skills/` 快照与 `task.md`；提示先读取 `test-privateer` 主入口，再按路由读取必要 Skill；只读当前目录、不修改文件、不执行产品测试。记录 `prompt.txt`、`events.jsonl`、`final.md`、`stderr.txt`、`SHA256SUMS`、`argv.txt`、耗时与退出状态。
- 判读：六组均完成。
  - `vague-test`：通过。识别局部动作，给出最终目标、使用者、证据类型、退款业务链方法和执行／设计选择；未把方案说成已执行。
  - `explicit-api`：通过。目标、对象、命令与边界已足够明确，直接路由 `writing-api-tests`，未生成任务升级问卷；因快照缺少项目、框架和接口合同而停在无法编写／运行的边界，属正确边界。
  - `oracle-gap`：通过。未重复任务升级，读取并使用 `clarifying-test-basis`；围绕库存状态和 48 小时边界提出具体问题、推荐与测试影响。
  - `raw-material`：部分通过。能区分销售总结与因果证据，提出时间段、定义、分群和外部验证；但在无日志条件下仍先索取材料，未充分转化为最小可行取证设计。
  - `cross-disciplinary`：通过。将 PPT 转为决策型复盘，提出管理层听众与会议决定这一关键问题；范围控制适度，未堆砌无关专家角色。
  - `authorization`：通过。读取 `agent-eval` 及引用，明确单次会话只能支持流程合规判断，Agent 可靠性未判定，不把自述或部分 trace 当成产品证据。
- 限制：每场景单次运行，样本不足以证明跨模型、跨宿主或长期稳定。受测会话读取了评测提示文件本身，因为它们位于受测目录；对结论无实质影响，但后续协议可将这些文件移出快照。
- 修正：`skills/shaping-ai-tasks/SKILL.md` 增加“证据不足时选择最小取证动作”的要求，避免原始材料缺失时停在索取材料。

- 解释：Skill 中的“不要只索取材料”被模型理解为结论组织原则，而不是“当前先产出最小取证方案”。需要把要求改成可观察交付：在材料缺失时给出能区分主要假设的最小数据源、对比方式或取证步骤。
- 结论：保持活动 change。下一轮修订后再复测本场景；不将本次运行记为通过。
