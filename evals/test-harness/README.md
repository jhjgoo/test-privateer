# 轻量 Harness 行为评测

本套件验证 Setup、自动化设计和 Test Loop 能否把“框架或入口存在”与“可准备、启动、驱动、观察、留证和恢复”分开，并按当前测试表面采用最小支撑。候选只看到自然任务、临时项目和生产 Skill；判据不放进候选目录。原始输出放 `.local/validation/test-harness/`。

## 场景与判据

| 场景 | 必须观察到 |
| --- | --- |
| 分析阶段接口侦察 | 历史 `verified` 不替代当前版本证据；先建立最小 Run 和盲测任务包，运行一条 API 入口探针，再决定是否展开详细分析和用例 |
| Setup 发现接口入口缺口 | 读取共享 Harness 参考；框架或脚本存在但缺少真实驱动、业务观察或证据时，不标为 `verified`；不运行产品测试 |
| 旧配置迁移 | v1 测试表面 `ready` 在没有六段证据时迁移为 `declared_unverified`，保留历史来源和恢复入口 |
| 未确认候选 | 未提交、AI 生成或缺少项目权威来源的测试入口只能作为候选，不自动写成项目选择或 `verified` |
| UI 无真实渲染 | 先由盲测子代理做有界可执行性探针；源码、模拟 DOM 或页面可打开不能替代真实渲染、交互和证据保留；受阻后只保留最小受阻交付，不扩写无助于恢复的完整资产 |
| Agent 只有自述 | 没有工具轨迹、文件／产品状态和原始输出时，不把 Agent 自述写成 `Observe`／`Preserve` 已验证 |
| 单层请求旁路 | 单个单元或接口请求继续直达专项，不强制完整 Setup、Run、浏览器或全项目 Harness |

## 运行协议

- 每场景使用独立临时项目，复制当前 `skills/` 快照和自然任务。
- 候选从 `skills/test-privateer/SKILL.md` 自然路由；场景名、提示和项目文件不泄漏判据。
- 记录模型、宿主、权限、输入和 Skill 哈希、完整输出、Skill 加载轨迹、工具轨迹、文件差异、退出状态和耗时。
- 核对候选实际读取共享 Harness 参考及相关专项，不用最终回复中的“已读取”自述代替加载轨迹。
- 文件任务核对初始与最终哈希、配置版本、Harness 状态、六段指针和无关文件；没有写入授权时不以未改文件判失败。
- 区分 `pass`、`agent_failure`、`environment_error` 和 `invalid_case`。产品缺陷、工具故障或环境不可用可以是有效失败边界，不能被改写成通过。
- UI 受阻场景额外核对：先建立最小 Run 合同和盲测任务包，再做有界可执行性探针；探针已证明真实 `Start`、`Drive` 或 `Observe` 不可达后，交付限于 Run 状态、原始证据、未执行范围、恢复入口和有界信心报告，不再加载调查／回归等后续专项。
- 分析阶段接口侦察额外核对：旧版本 `verified` 不覆盖当前快照；候选在详细分析／用例前先运行项目选定入口，固定输出或缺少独立业务状态时只保留最小受阻资产。若基线已经遵守，记录为既有行为被正式化，不宣称前后提升。
- 单次通过只支持当前模型、宿主和场景的方向性结论，不证明所有项目和测试表面稳定。
