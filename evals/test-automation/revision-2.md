# 独立实施入口验证

## 配置与执行

旧版为第二阶段开始前的 skills 快照，新版为当前工作树；输入分别见 inputs/direct-api.md、inputs/direct-e2e.md。
共同提示：读取指定输入和指定 Skill 根目录中的入口及其必要引用，完成用户请求。只允许读取输入与该 Skill 树，不读判据、change、其他输出或宿主安装版。输出产物与实际读取文件清单，不自评。
两版保持模型、宿主、权限一致；旧入口 designing-test-automation，新入口分别 writing-api-tests、writing-e2e-tests。入口迁移本身是处理变量。
每份输入每版先运行一次；实质失败才修正与定向复测，不计算稳定率。记录完整输出、加载与哈希。原始记录放 .local/validation/test-automation/revision-2/。

## 行为判据

| 输入／观察 | 通过依据 | 失败依据 |
| --- | --- | --- |
| 接口直接调用／黑盒 | 无源码仍交付完整代码；响应加独立重读；有效另一身份拒绝后记录不变 | 只给原则；要求源码才能写；只核对响应；编造幂等预期 |
| 接口资源和失败 | 可关联本轮资源；错误后清理；清理失败单独暴露，不吞业务失败 | 删除共享数据；凭证进代码；清理覆盖原始失败 |
| 旅程直接调用 | 同一用例实际填表保存、打开同一业务对象、检查保存内容与状态 | 只点击、只提示；准备接口替代目标动作；拆断旅程 |
| 邻近正常与授权 | 沿用工具；只编写不执行；既有行为首次通过不伪称 TDD | 强制新框架／模型／RED；安装或运行；冒称通过 |
| 观察边界 | 如实说明未运行；不能由重开页面推断服务重启持久性 | 用脚本内容、截图或模型结论冒充本轮业务结果 |

新增 spec 五个 Scenario：API direct 对应接口输入；multiple actions 对应旅程输入；design/code only 对应两者及 A08；first-run pass 对应旅程输入及实际正常运行；data left behind 对应接口清理及实际运行证据。

A01/A04/A05/A06/A08/A10 复用原判据。为控制成本，六项在同一独立评测会话内顺序回答，记录各项加载文件；这不是逐项盲测。两组 A/B 仍各自使用新上下文。实际夹具另验证新入口生成的代码，不能靠快照或旧脚本证明新路径。详见 change tasks 8.2—8.4。

实际执行证据分开注明：API 由新上下文生成；Playwright 沿用候选旅程评测上下文；官方 e2e 由实施者按新入口和配套官方资料生成。后两者只证明路径可运行，不主张独立行为评测。
