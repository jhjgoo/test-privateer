## 观察结果

### 功能／公开 API Case：定性输出改善

修改前的四条代表用例把下列内容写进了前置或操作：

- 用 `tenantId` 证明调用方与目标租户不同，但接口没有提供该观察结果；
- 用 `releasedAt` 非空准备“已解绑”状态，但没有绑定／解绑操作入口；
- 要求“使 Prisma 查询抛出异常”，却没有故障控制手段；
- 把内部查询顺序写成外部执行者需要验证的目标。

公开路径、Bearer Token、HTTP 状态和 `messageCode` 可以保留，但前置和证据要求不能直接执行。

修改后，同样四个场景改成可准备或可观察的业务动作；公开路径、Bearer Token、HTTP 状态、`messageCode` 和响应泄漏检查仍保留。缺少管理或故障入口的 Case 明确标记为当前不可执行。

### TDD 单元测试：未观察到退化

Baseline 与 candidate 均完整保留公开 seam、输入输出、fixture、替身、执行状态和 RED 原因，并排除 seam 以下实现细节。固定输入没有真实源码和命令，两侧均如实保留缺口，没有编造已运行 RED。

### 混合请求：完成规则通过，未形成版本差异

可复现的单次 CLI 对照中，baseline 与 candidate 都分别生成了功能 Case 和单元测试切片，并分别标记未执行／未取得 RED。Candidate 的路由完成规则在该场景下得到满足，但 baseline 也通过，因此本次运行只支持“无退化”，不能支持“混合路由已经稳定提升”的结论。

## 结果

当前证据支持受限结论：功能／公开 API Case 的生成结果在同上下文前后观察中改善；单元测试同样只支持本次输出未观察到下降。只有混合请求保存了独立 CLI 上下文和精确配置；该运行证明 candidate 满足完成规则，但没有观察到相对 baseline 的提升。静态契约测试只保护规则及其所在章节；这些记录都不构成 GPT-6 Astra 或统计稳定性证明。`~/.agents/skills` 中的已安装副本仍是旧版，重新安装或同步后才会影响从该路径发起的新调用。
