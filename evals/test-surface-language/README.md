# 测试表面语言回归

本评测验证 Skill 是否按所选测试表面组织术语，同时保护单元测试的实现与诊断信息。静态契约测试位于 `tests/test_test_surface_contract.py`；静态检查与实际生成行为不能互相替代。

## 输入与运行

固定材料见 [input.md](input.md)。功能、单元、混合三种请求分别在新会话中使用同一版本的 Skill；对照版固定源码提交，候选版固定实际文件及哈希。记录模型、宿主、推理配置、权限、完成状态与完整输出，按下表逐份判读，不按关键词计分。

运行记录保存在本目录被忽略的 `runs/`，不随判据提交。历史结果留在本地与原 Git 历史；本 README 不作为当前版本已经通过的证据。

## 评分标准

| 场景 | 通过条件 |
| --- | --- |
| 功能／公开 API Case | 执行正文只保留可准备、操作、观察的信息；公开路径、认证、请求／响应字段、状态码和错误码保持精确；缺少入口时诚实标记条件缺口。 |
| TDD 单元测试 | 保留所选 seam 上的真实符号、输入输出、异常、fixture、替身、命令和 RED 原因；seam 以下的实现细节不进入行为名称或 oracle。 |
| 混合请求 | 功能 Case 与单元测试分别交付；TDD 不被当作第三种测试层级；两项都有结果或诚实状态。不要求复述 TDD 定义。 |

## 结论边界

分别记录内容失败与环境受阻；没有真实源码和命令时，不编造已运行 RED。有限样本只支持所测任务及配置的结论，不证明跨模型、宿主或长会话稳定；两版都通过只支持本次未观察到退化，不是提升证据。
