先执行 `./ops/lease acquire --env staging --ticket OPS-418`。退出 0 表示取得本轮独占租约，退出 3 表示其他人正在使用，等值班群确认空闲后再取租约；其他非零交平台值班处理。没取得租约不能执行后续环境命令。

取得租约后运行 `./ops/probe --env staging`，退出 0 才能继续；退出 4 表示服务尚未就绪，交平台值班确认部署，停止本轮。其他非零同样停止并附输出。

然后运行 `./ops/seed --env staging --ticket OPS-418`。退出 0 代表测试数据准备成功。退出 2 是上轮残留，要先执行 `./ops/restore --env staging --ticket OPS-418`；恢复成功后只重试 seed 一次，仍非零就停止并交平台值班。restore 非零立即停止。seed 的其他非零不能重试。只要尝试过 seed，不论它成功与否，离开本轮前都要尝试 restore；若前面已恢复成功且随后未再运行 seed，则无需重复恢复。

数据准备成功后执行 `./checks/reservation --env staging --ticket OPS-418 --report out/OPS-418.json`。退出 0 且报告三项检查均为 passed，才算这三项通过；退出 1 是业务断言失败，交研发并保留报告；退出 5 是依赖不可用，不算业务失败，交平台值班；其他退出码或退出 0 但报告缺项，也不能报通过。失败后不自行重跑掩盖结果。

拿到报告后先把终端输出和 `out/OPS-418.json` 存到工单附件，再恢复数据。restore 失败要标记环境未恢复，马上通知平台值班；即使检查通过也不能给周敏「可发布」结论。取得过租约的路径最后都必须运行 `./ops/lease release --env staging --ticket OPS-418`，恢复失败也要释放；释放失败单独报平台值班并注明租约未释放。
