# 用户请求

我们做冷链仓库入库，周一要评审新规则。请根据下面材料整理一份测试评审说明，让品控负责人和测试同事能看懂现在该确认什么、哪些检查能先做、哪些结果还不能下结论。我们需要据此安排下一轮测试。

# 已知材料

每批货有唯一批次号。扫码登记后为「已登记」，上传运输温度记录后系统检查。温度每分钟采一条，超过 4℃ 的连续分钟数为一次超温时长；不连续的两段不能相加。规则写的是「任一连续超温时长大于 T，进入待复核；否则进入可入库」。比较符号已经确定为严格大于，T 的单位是分钟，但需求和测试环境说明都没有给出 T。品控负责人负责确认当前生效配置。旧会议记录里有一次 12 分钟的超温案例，只记了最终由人放行，未记当时配置和系统初判。

记录缺一分钟或同一分钟有两条不同温度时，直接进入「待复核」，不得把缺失当作正常温度，也不得自行挑一条。恰好 4℃ 不算超温。无超温且记录完整的批次可以直接成为「可入库」。

「待复核」由品控人员提交通过或拒绝的结论，提交后状态均显示「已复核」，结论另外保存。「已复核」只表示审查做完；结论通过且外包装检查合格后，品控人员才能点击放行，变为「可入库」。结论拒绝的批次保持「已复核」，另起退运申请。外包装不合格即使复核通过也不能放行。仓管只能对「可入库」批次执行入库，其他状态点击入库应被拒绝，货位和库存都不能变化。

复核通过不会修改原温度记录。上传接口按批次号防重复，同一批次重复上传相同记录只返回已有结果，不新增批次、不清除复核结论、不把已放行状态退回。前端和接口都要保护放行及入库规则，不能只测页面按钮。
