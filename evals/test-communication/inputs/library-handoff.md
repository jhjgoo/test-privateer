# 图书馆预约：测试分析与功能用例

使用黑帆测试官，先调用 analyzing-change-for-testing 完成测试分析，再调用 designing-test-experiments 设计对应的功能用例。独立处理以下材料，在同一回复中分别交付这两项产物。不执行产品测试，不修改文件，不作上线判断。

分析覆盖下面全部业务规则，说明测试重点与安排。详细用例只设计三条：先冻结再归还图书；先冻结再取消待领取预约；正常状态下取消排队预约。用例关联分析中的测试项。真正同时发生的请求、超时与其他场景仍留在分析中，不把这三条顺序场景称为完整覆盖。

## 业务规则

以下规则沿用 branch-analysis.md 的合成场景，并非真实项目需求。

仅有效借阅证可预约，失效证不生成预约。可借库存大于 0 时预约进入待领取并占用一册；无库存则进入排队，不占用库存。同一读者对同一本书只能有一笔未结束预约；已完成或已取消不阻止新预约。读者可取消排队或待领取预约，取消待领取时释放占用，取消排队不增加库存。

归还或取消释放库存后，按排队时间先后分配，同一时刻按预约编号升序；轮到失效证读者时取消其排队项、跳过并尝试下一位，不把库存给失效读者。待领取超过 48 小时未领取自动取消并释放库存；恰好 48 小时仍可领取。管理员冻结某本书时不接新预约，但已进入待领取的读者仍可领取；已排队者暂停分配，解冻后继续保持原次序。

最先关注冻结与库存释放同时发生时不能给排队者分配，以及取消待领取后不会多释放库存。卡证、排队顺序和超时边界同样要有明确安排。

## 模拟页面约定

以下是为这次评测补充的虚构页面能力，不是从真实产品调查所得。可以作为用例设计依据，不代表环境已经存在或可用。

- 读者在“图书列表”查看可借册数并提交预约。
- 读者在“我的预约”查看本人预约状态，取消排队或待领取预约。
- 管理员在“图书管理”冻结或解冻一本书，查看冻结状态和可借册数。
- 管理员在“借还登记”登记借出或归还，也可为待领取预约办理领取。
- 管理员在“预约队列”查看预约编号、读者、预约时间、状态及排序。

测试同事可按数据准备要求准备有效借阅证读者和独立图书；具体账号、准备工具、目标版本尚未提供。没有已执行记录、已知缺陷或真实环境访问权限。预约显示结果何时可视为处理结束、如何控制真正并发和时间边界，也未提供约定；需要时保留缺口，不编等待秒数或后台操作。
