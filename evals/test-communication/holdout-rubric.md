# 私有留出判据

此文件只供评审者使用，不能送入被测任务。两份输入分别评审，禁止用一项改善抵消另一项关键语义错误。评估对象是测试技能组合的最终中文交付；被测版本、模型、推理设置、宿主、工具权限与实际输出由运行方另记。这里未进行模型采样，不能据此宣称版本改善。

评审阅读完整输出，记录每个结论的原文位置及其对读者决定或行动的影响。允许不同标题、段落、表格、清单或局部流程图；不以关键词出现、篇幅、固定字段、是否采用某种格式判通过。读者必须能在没有解释者补充的情况下完成下述决定。若输出引用外部事实，必须能够区分来源与输入事实。

## 一、threshold-state.md

### 必须保留的语义

1. 读者知道 T 的实际值未知，不能从 12 分钟案例推导；案例有人放行不能证明系统阈值。读者能找到品控负责人需要确认的具体事项：当前生效的分钟阈值。输出不能把示例、假设或任意数字写成已知规则。
2. 连续时长严格大于 T 才触发该路径；等于 T 不触发。多段不能累计，4℃ 恰好等于温度边界不算超温。符号测试数据可以围绕 T 设计，但拿不到实际配置时不能声称已验证数值边界。
3. 缺记录或同一分钟温度冲突直接进入待复核，完整且无超温可以先验证直接可入库；未知 T 不妨碍这些独立检查。不得把全部测试笼统挂起，也不得伪造执行证据。
4. 复核通过和拒绝都可能处于已复核；只有通过、包装合格并执行放行动作才能变成可入库。包装不合格不能放行，拒绝的批次另起退运申请。状态名不能被当作同义词或仅写成一条无分支的成功链。
5. 入库只允许可入库，拒绝其他状态时货位和库存不变；页面与接口都需覆盖。复核不改温度原始证据，相同记录重传不能新增批次、清除结论或使已放行退回。可把测试合并组织，但不得漏掉这些独立后果。

### 读者任务

品控负责人能确认缺失配置而不是回答宽泛的“完善需求”；测试同事能区分立即可做的检查与等待 T 后才能判定的边界检查，并知道输入、预期结果和观察位置至少应是什么。双方能识别“已复核但仍禁止入库”的实例，不必从术语表自行拼出控制规则。输出应据此支持分派下一轮工作，不能止于复述原文或泛化测试建议。

关键失败：编造 T；把已复核当作可入库；把人工放行案例当成阈值证据；把未执行说成通过；改变任何保护库存或证据的业务规则。

## 二、temporal-handoff.md

### 必须保留的语义

1. 读者能从指定目录、staging、工单号开始，复制使用已供命令，知道取得租约之前不能碰环境。租约占用的等待条件与其他获取失败的移交对象不同，不能混成盲目重试。
2. probe 是本轮取得租约后的检查，成功才准备数据；当前不就绪需停本轮并交平台。昨日 probe 不可沿用。昨日没有完成准备或业务检查，不存在回归通过证据。
3. seed 退出 2 才允许先 restore，再且仅再试一次；restore 失败、其他 seed 错误或重试失败均停止。输出不能建议任意重试或在准备未成功时跑业务检查。
4. 业务检查须同时满足退出 0 与三项报告 passed；业务失败、依赖不可用、其他错误和报告缺项不能报通过，接手人能据此选择研发或平台。应能判断三项受测行为是什么，以及有限范围通过不自动等于全量发布保证。
5. 存证早于恢复，恢复早于最终租约释放。尝试过 seed 的路径需要恢复；已恢复成功且未再 seed 的路径无需重复恢复。恢复失败仍释放，已取得租约而在 probe 等早期停止也要释放。任何清理失败都不能在“测试通过”一句中消失。
6. 恢复失败标注环境未恢复并交平台，明确不能给可发布结论；释放失败另报租约未释放。即使报告三项通过，接手人也能判断清理异常如何影响交付。不得新增未经提供的修复、生产替代、重跑或实际执行动作，不为普通工单引入 OpenSpec 前置流程。

### 读者任务

接手人能决定明天从哪里重新开始，依次执行什么，在每个已供异常分支是继续、等待、停止还是移交；能在提前终止时仍完成所需清理，能向周敏报告验证范围、当前证据、失败性质和环境/租约是否收尾。命令正确但组织方式迫使读者在多处自行找条件、猜异常出口，应记录为可用性不足；叙述流畅却丢失分支、顺序或完整命令，不能判通过。

关键失败：无租约执行；准备失败后跑检查；把退出 0 单独当通过；无上限重试；将昨日未跑误报通过；先恢复再保存唯一证据；提前停止漏释放；恢复失败仍给可发布；修改目标环境或实际执行。

## 综合判断与证据边界

- 语义合格：所有关键约束正确，读者任务可完成；可接受合理组织形式和明确标注的补充建议。
- 表达有缺口：无关键语义错误，但至少一个读者任务需要自行补条件、跨段拼接关键决定或猜测下一行动。记录具体卡点，不仅评价“太长”“术语多”。
- 语义不合格：出现关键失败，或遗漏使读者可能做错业务决定或操作的规则。好看、简短、术语解释完整均不能抵消。
- 不可评：样本缺失、未用完整输入、运行环境失败、泄漏私有判据或未冻结候选；应区分案例/环境问题与被测产物问题。

比较版本时逐案报告关键语义是否保真、哪些读者任务变得可完成、哪些出现退化，附实际输出证据。两例只支持这两类任务的有限判断，不支持跨模型、宿主或长会话的稳定性结论。冻结候选之前不得向实现方透露输入事实或上述细项。
