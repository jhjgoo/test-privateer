# Design

## Context

见 proposal 的真实使用问题。原会话读取时任务确实为 20/22；当前的 22/22 不能反推初始化当时读错。共享更新纪律只有在读取测试 Skill 时才生效，使用方开发流程没有相应完成条件。本仓库已有未提交的已归档变更，实施保留其内容。

## Goals / Non-Goals

- 把事实调查留给 Agent，把实质范围、时点与授权选择交给用户；短问题无需固定模板。
- 用现有项目规则接通维护，不新增 Skill、后台同步、全局钩子或第二份账本。
- 不要求每次任务都改配置与 TCO；不把文档更新等同于新测试证据。
- 不实施既有验证器 change，不修改使用方实际项目，不归档本 change。

## Decisions

1. **共享方法单一维护。** 在 `artifact-routing.md` 补决策表达和“开发与测试资产联动”，Setup 直接读取；主入口及建图／信心交付引用同一规则。无需复制格赖斯全文，也不声称符合完整 ASD-STE100。
2. **Setup 接入项目入口。** 调查已有 AGENTS、CLAUDE 或等价入口及其引用链；有等效约定则复用。缺失时在当前宿主实际读取的项目入口合并一个短约定，已有文档不得覆盖。默认沿宿主约定使用 AGENTS；无法确认入口则报告未接通，不创建任意名称文件。配置只索引该约定，不保存可执行规则。遵守使用方变更流程，不强制安装 OpenSpec，也不修改第三方 Skill。用户禁止规则修改、只要预览或不可写时保留 partial 和恢复动作；源规则冲突时 blocked。
3. **按影响维护。** 配置承载测试方式、治理及入口；TCO 承载业务与系统关系、覆盖和长期风险；任务与 Run 承载短期进度及原始结果。交付时由当前合成者更新受影响字段，无影响不写。仅证据不足时不自动升为 verified，也不自动接受风险。
4. **归档是迁移事件。** 以实际归档结果修正当前配置／TCO 中受影响指针，不预填未来路径，不改历史证据。不得把接入约定当作归档授权。
5. **防重复与竞争。** 原地维护唯一约定，保留人工规则、已有决定、换行和权限。写前核对受影响权威来源与目标内容，检测并发变化后重新合并；回读确认目标字段和引用，没有相关变化不更新校准日期。不同文件失败时报告实际部分结果，不宣称跨文件原子事务或自动回滚他人的更新。

## Validation

- 直接调用 Setup 的缺失决策和已确认邻近样本，检查共享参考实际加载、同维选择和正常短答复。
- 初始化在临时项目接入约定，随后独立冷启动开发会话只读项目规则进入任务，不由提示直接注入维护答案；检查测试入口迁移、运行证据和对应 TCO 变化。
- 从初始化产物分叉归档、无关改动及禁止接入边界；核对历史证据与人工内容保持，避免只看“已完成”自述。
- 保存完整输出、读取／工具轨迹、文件快照、哈希、差异与退出状态。有限样本仅支持当前模型／宿主；不宣称普遍改善。

## Risks / Trade-offs

- 项目规则属于提示约定 → 回读只证明写入，真实冷启动评测确认消费，不宣称安装了自动钩子。
- 宿主入口不同 → 按实际入口适配，等效规则复用；不散布多个副本或机器绝对路径。
- 规则修改扩大初始化范围 → 预览明确包含该最小变更，遵守现有授权和项目流程；明确排除时如实部分交付。

## Migration Plan

不改配置 v2 的状态枚举；旧配置下次 Setup 校准时删除短期进度副本并索引已接入的维护约定。规则撤回时只撤回本次新增约定，保留原文与历史证据。实施、评测完成后保留活动 change，用户确认后另行同步规格与本地安装。

## Behavior Feedback

- 首轮直接 Setup 已读共享规则且选项同维，但推荐理由和当前工作影响交代不足。共享表达补明确的理由与工作影响，保留失败并复测目标及已确认邻近场景。
- 冷启动开发确实更新入口与 TCO，但在配置中写入 `../` 证据链接。把既有配置路径约定补入共享维护入口，区分配置根目录路径和 TCO 文件相对链接，再复测迁移；不修改原候选输出。
- 2026-11-10 实际使用审计：全局新／项目旧副本并存时，只检查目标文件存在就误报联动成功；已有 TCO 与同轮任务来源冲突仍未校准；最终问题回退为“延期或指定入口”；新增协作义务被误归纯工具豁免。用户已要求在本 change 修正。
- 修正沿未来实际入口读取方法内容，既有结论与来源定向对照，最终问题发送前自校，按新增义务判定流程类别。把 Setup 末尾十五项状态复述收拢为引用、证据和问题三项交付检查，避免用长清单代替判定；不新增状态、生产脚本或固定决策卡。
- 补混合安装及已对齐邻近样本、陈旧配置与未变化邻近样本、长配置后范围确认及已延期样本、协作变更与纯工具豁免，并从实际生成产物验证冷启动消费。真实项目只作为审计证据，不直接修补来制造通过。
- 修正后的真实评测又暴露两个交叉边界：未决选择使 Agent 只改草稿而保留文件中已知失实的 ready／verified；重复初始化因基线提交迁移顺带重写正确正文。消解“所有选择关闭才写”与“未决只阻塞相关工作”的冲突；已有写入授权下先修已证实错误，明确每处维护差异的依据。保留失败后复测受影响路径。
