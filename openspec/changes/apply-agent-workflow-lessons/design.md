# Design

## Decisions

1. **共同契约放在 `running-test-loop/references/`。** 只有完整 Loop 的冷启动盲测使用它；普通单层测试不新增必读步骤。
2. **错题本只加筛选条件。** 不改变证据字段、统计口径、权威位置和晋升流程；pstack 的 reflect 轻量化不替代本仓库的真实事件要求。
3. **方案质检只加一个结构信号。** 重复特判是线索，不是缺陷本身；仍需检查规则依据和边界后再判断。
4. **测试表面隐藏执行 nuance。** 可固化的准备、驱动、观察和判定信息进入 Case 字段、脚本、测试标识或断言；只有专业判断保留为人工检查，不写成隐式经验要求。

## Risks / Trade-offs

- worker 指针不能证明子代理实际读取；仍依赖任务包、调度轨迹和隔离 handoff 审计。
- 过严筛选可能丢弃高后果单次教训；已有“项目已确认高后果约束可单次晋升”规则继续优先。
- “反复”没有固定次数阈值，按同一边界和机制判断，避免机械规则误报。
