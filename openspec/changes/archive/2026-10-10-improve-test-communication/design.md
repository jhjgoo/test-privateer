### 2. 一处共享方法，专项内容留在原位

重组 `skills/test-privateer/references/artifact-routing.md` 的表达章节，不继续叠加长段禁令：

- 围绕读者当前要理解、决定、执行或验收的事组织信息，先让重点可见；缺少必要背景时简要补足。
- 使用熟悉、具体的对象与动作。同一概念沿用同一名称；必要技术术语保留，理解有障碍时就近解释，不机械翻译。
- 仅合并作用相同的重复。比较可用表格，时序和分支可用图，文字已清楚就不另画图。覆盖清单和执行详情有不同用途时可以同时保留。
- 精简后回看原任务：条件、例外、未知、来源和接手所需信息是否仍在。不给缺少依据的内容补出“确定答案”。

以上是选择表达的思路，不是逐项输出的栏目。报告突出本轮结论、限制与后续重点；计划围绕可验收结果组织，执行条件放在动作附近。充分的短答复保持简短。

人工复核又发现长报告以加粗行代替全部标题，缺少可扫描、可导航的章节层级。共享表达补充语义标题规则：按内容从属关系组织文档、主要章节和必要的子章节，加粗只作段内强调；不固定章节名或数量，短答复不强制分章。复用已生成的报告作为失败证据，只补测报告与短答复，不扩展评测矩阵。

B4 日志确认已加载共享规则，但生成报告仍全用加粗章节，不能判通过。B5 将 Markdown 层级写入报告 Skill 的“信心说明”交付约定，明确对话交付也适用；共享参考只保留通用语义原则，避免重复维护具体层级。报告和短答复各补一次，不按成功样本筛选覆盖 B4 失败记录。

用户随后指出句子仍长，Skill 本身也啰嗦。B6 只替换共享表达中的长段指导：用短指令、一句一事、主动语态和名称一致四条原则收束写法。英文 20 词仅作参考，不设中文硬性字数。保留条件、技术精度、标题与执行计划要求；不向专项 Skill 再复制一套规则。复用 B5 报告和 B3 计划作为历史对照，候选仅补测报告、计划、短答复各一次。核对实际操作是否更易辨认及信息是否保真，不以字数降低判通过，也不将历史对照称为同期 A/B。

B6 的计划与短答复保留原任务，但报告的 C-022、C-023 仍用分号串联操作。B7 只把共享原则中的“拆成步骤”明确为“分行列步骤”，并补测一份报告；保留 B6 失败位置，不因部分段落变短就判整体通过。不继续为每个长句补规则。

B7 实际报告将共用操作展开为七步，测试条件、未知与追溯边界仍在。部分用例说明仍有长句，不能声称逐句遵循或整体验收。规则保留这一版，交给用户看真实输出，不追加全面重测。

用户已确认 B7 报告阅读效率明显提升，并同意继续评阅测试分析和功能用例。复用图书馆规则，在新输入 library-handoff.md 明示补充的模拟页面约定。当前版本单次生成两类交付，详细用例只选三条顺序场景；其余规则仍保留分析安排。此次用于人工可用性判断，不是新的 A/B、独立留出或真实产品执行，不据此修改生产 Skill。

首次从主入口运行未加载 analyzing-change-for-testing，不能用于该 Skill 验收。保留首次输出及轨迹，任务明确点名两个目标 Skill 后补一次生成；不注入写作规则，不覆盖失败记录。此补测验证明确调用的产物，不宣称自动路由已经修复。

显式调用在一次宿主中断后恢复完成，两个目标 Skill 及模板均已加载。原稿交给用户评阅，不先润色；标题层级、独立审阅声明缺证和超时释放并发安排另列待修，不能以报告已获认可代替这些问题的验收。

用户评阅后指出分析与用例仍缺章节、关键要点强调，且长句过多。B8 将共享标题原则改为明确的 Markdown 写法，并区分标题与段内强调；长说明不挤进表格。分析入口将模板适用范围从文件扩展到对话完整交付，用例入口取消“表格优先”的导向。两个入口在交付处引用同一共享表达，不复制整套规则。复用原图书馆任务补测一次，同时检查报告和短答复；不手工改生成稿，不将本轮可读性修正扩大为独立审阅和并发范围问题均已解决。

B8 三份输出均完成。图书馆用例的关键预期得到强调，但分析与用例仍无 Markdown 标题；报告保留层级，却把开头整段加粗。短答复保持简短。实际加载轨迹排除了漏读共享规则和模板，不能宣称本轮可读性通过。B9 仅在主入口最终组装处明确 Markdown 标题约定，并移除两个专项入口本轮新增的重复检查提醒；保留模板对话适用性。只补测图书馆原任务，不再次扩展矩阵。其他未解决问题继续保留。

B9 原稿已形成分析、用例和业务分组的真实标题层级，关键库存预期及前序完成条件得到强调。独立前置和操作易于定位，但开头、证据要求等仍有长句；本轮止于有界改善，不再追求每句一致。无独立审阅证据及超时释放并发安排仍未解决，整体 change 保持开启。B8 相邻检查不冒称 B9 全量回归。

用户认可 B9 整体结构，并要求继续优化长句。B10 仅替换共享表达中的对应指导：说明段落也一句一个判断，结论与理由分句；需要分别核对的证据、缺口和限制列成清单，简短内容不强拆。不新增字数门槛或专项规则副本。原图书馆任务补测一次，以单条公开 API 用例保护精确契约，以短答复保护适度表达；每项一次，不重跑完整 A/B。既有独立审阅与并发范围待办不在本轮文字修正中宣称解决。

B10 保留了图书馆文档的章节，范围与交接说明更清楚，但三条用例的最小证据仍串成段落。单条 API 用例的证据已列清单且契约保真；短答复未扩写。B11 将证据清单要求移到 designing-test-experiments 的最小证据条目，共享段落只保留一般拆句方法。只再生成图书馆原任务一次，保留 B10 未达到目标的记录。

B11 三条证据均分行列出，时点、对象及数量判据保留，但全文标题回退为加粗段首，独立审阅完成声明也没有工具证据。仅确认局部改善，不判整体验收，不由单次结果推断回退原因。保留该候选与原稿，停止本轮扩测；长说明、标题一致性和既有内容缺口仍为待办。

现有专项边界继续有效：功能用例使用可准备、操作、观察的入口；单元测试保留符号、替身、诊断和真实执行状态；报告区分观察与判断；用例独立可执行、可追溯。已知规则不能随未知细节一起被推迟。

## Validation

### 一次 A/B，加人工评测

先实施，再固定候选文件。A 是上述基线，B 是本轮实际候选文件；不再设置“基线＋简短注入提示”的第三配置。旧记录中的 B／F 标签只属于历史轮次。

首轮复用七组输入，两版各一次，共 14 份输出：报告、业务澄清、复杂分支分析、执行计划、功能／单元混合请求、单条用例、已充分的短答复。具体路径和运行配置在 `evals/test-communication/README.md` 维护，不再新建评测框架或另铺留出、注入、入口三套矩阵。

双方使用相同任务、模型、宿主、推理设置、权限和新会话，读取各自真实 Skill 文件。默认沿用目标请求模型 gpt-6-astra／high、原生 Codex CLI；运行前记录可用版本与实际命令。保存输入、文件哈希、输出和加载轨迹。漏读共享参考如实记录为接入问题，不用注入补成通过；无法读取文件或环境失败与内容失败分开。

先按源材料核对事实，再比较三个方面：

- **重点与理解：** 是否容易找到核心问题、结论和必要依据，术语是否适合读者。
- **行动与用途：** 是否足以作出判断或接手操作，前置条件、验证和完成条件是否完整。
- **准确与边界：** 规则、例外、技术精度、测试层级、未知和执行状态是否保真。

AI 自校辅助找问题，不替代用户对可读性和使用价值的判断。挑选报告和执行计划等 2～3 组代表结果，附相同背景与完整输出交给用户；不只摘最优片段，不要求用户填写复杂评分表。允许“两版都不好”，也接受具体一句话的反馈。历史版本已揭晓，不冒称严格盲评。

### 修正与停止

整体更易读、关键任务能继续且未发现未解决的实质退化，就可结束这一轮；不要求逐句优胜或每次完全复现。补造规则或入口、丢失判定条件、削弱已知测试点、混淆执行状态不能由阅读收益抵消。

有问题只修改控制该问题的规则，复测受影响样本及相邻正常场景。无关场景不反复生成，不为普通措辞波动加轮次；若需要扩大范围或重跑整套，先说明原因并更新本 change。原始记录仍放忽略目录，可复用输入与判据正常跟踪。

运行现有单元契约、XMind 自检、OpenSpec 与差异检查。静态通过只证明相应文件契约；A/B 和人工反馈支持的结论仅限本次样本、模型与入口，不推导跨宿主稳定性或统计显著。
