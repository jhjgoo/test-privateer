# Design

## Context

`shaping-ai-tasks` 已有任务契约、事实与决策、证据缺口和路由边界；`prompt-eval` 与 `agent-eval` 已要求固定配置、最小场景、Oracle、加载轨迹和工具证据。本变更只补一个跨入口的观察框架，不能取代这些已有契约。Skill 包使用 Markdown 作为运行时规则，静态测试负责结构保护，真实模型行为评测负责观察入口是否真的产生目标行为。

## Goals / Non-Goals

**Goals:**

- 把格赖斯四项准则转成四个可定位的行为问题：数量、质量、关系、方式。
- 在任务升级阶段做轻量自校，在 Prompt／Agent 评估阶段做可报告的失败分类。
- 保持证据、授权、路由和实际轨迹优先；让信息增删、主张校验和下一步可执行性有明确观察点。
- 通过最小成对场景覆盖正常、缺失、无关和越权边界。

**Non-Goals:**

- 不新增全局系统提示词、人格规则或固定回复模板。
- 不要求所有短答复都输出四项检查，不以字数、礼貌或单一分数衡量质量。
- 不改变主入口路由、工具权限、Skill 安装格式或现有评测平台。
- 不把一次模型运行、模型自述或静态文字命中当成普遍行为保证。

## Decisions

1. **在现有入口内落地，而不是新建共享 Skill。** 任务升级、Prompt 评估和 Agent 评估是实际决策点；新增共享 Skill 会增加路由和加载成本，也容易让模型只看到摘要而跳过正文。四维说明保持短小，详细证据规则继续由现有专项维护。

2. **用四维标签替代总分。** 数量、质量、关系和方式可能互相冲突，例如删去背景能改善数量却损害方式所需的执行条件。报告分别记录维度、证据和影响，保留冲突与未知，不做平均分。

3. **把四维绑定到可观察证据。** 数量看任务所需条件和无关动作，质量看主张与来源／工具结果，关系看目标、授权、路由和工具轨迹，方式看对象、动作、顺序、边界和判定。模型“遵守了准则”的自述不作为证据。

4. **先扩展成对评测材料，再改 Skill。** 先加入能捕捉基线错误的自然任务和判据，再用最小文字改动让入口行为可观察；评测结果只用于本配置下的方向性判断，并保留环境错误和无效案例。

## Risks / Trade-offs

- **[Risk] 数量准则被误读为越短越好** → 明确“最小充分”并要求保留判定信息、证据和边界；契约测试检查反删关键条件。
- **[Risk] 四维变成另一套重复清单** → 只在已有任务契约和评估步骤增加一段映射，详细方法继续引用现有 Skill。
- **[Risk] 评估标签替代真实归因** → 要求同时提供实际读取、工具轨迹、文件差异或运行结果，并区分环境受阻、无效案例和 Agent 失败。
- **[Risk] 外部文本注入污染“关系”判断** → 场景明确外部材料是数据而非指令，评审检查实际路由和授权动作，不按最终文案单独判定。

## Migration Plan

1. 先写契约测试和可复用自然场景，确认当前 Skill 缺少目标词或行为约束时测试会失败。
2. 更新三个 Skill 的最小段落，再运行静态契约、包检查、OpenSpec 严格校验和成对行为场景。
3. 若评测发现过度追问、无关扩展或把自述当证据，优先修正对应入口，不扩大为全局规则。
4. 本 change 在用户确认前保持活动状态；确认后再同步规格、归档并同步本地 Skill。
