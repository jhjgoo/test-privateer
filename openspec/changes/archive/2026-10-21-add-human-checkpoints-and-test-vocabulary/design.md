# Design

## Context

Matt Skills 的 `wizard` 说明了一个重要问题：有些步骤只有人能做，例如凭据、第三方后台、审批或一次性迁移。Test Privateer 不需要生成通用 bash 向导，但需要把人工步骤纳入测试证据链，否则 Agent 会停在口头等待，或把用户返回的结果与亲自执行混淆。

领域语言层则对应 `domain-modeling` / `codebase-design` 的启发：共享词汇应运行在专项 Skill 之下，并有单一权威位置。当前 `artifact-routing` 已有基础，适合轻量扩展而非新建 Skill。

## Goals / Non-Goals

**Goals:**

- 人工步骤有可交接、可恢复、可判定的检查点。
- 人工结果保留来源和证据边界。
- 术语定义唯一，专项 Skill 只保留使用规则和指针。
- 领域语言层保持轻量，不变成百科。

**Non-Goals:**

- 不实现通用 wizard、交互 shell、凭据管理器或自动审批流。
- 不要求每个人工动作都编号或建任务。
- 不把 SFDIPOT、MFQ、PPDCS 的完整方法搬进主入口。
- 不新增宿主专属配置。

## Decisions

1. **人工检查点放在 `running-test-sessions`。** 它是执行阶段权威；其他 Skill 遇到人工等待时交回 handoff，不各自定义第二套状态机。
2. **主入口只做恢复和推进边界。** 主入口负责新会话恢复未完成检查点、禁止在结果未回填前推进依赖链，不复制执行细节。
3. **术语权威继续放 `artifact-routing`。** 它已被多个 Skill 引用，能同时服务表达、编号和阶段交接。
4. **方法缩写保留原名。** SFDIPOT、MFQ、PPDCS、TCO 等在领域语言层给一句定位和方法 Skill 指针，详细方法留在专项。
5. **检查点状态保持最小。** 仅维护待确认/待执行/执行中/已完成/失败/取消；不记录聊天过程或无关人工操作。
6. **行为验证选三个代表场景。** 生成检查点、回填后恢复、术语漂移纠正；另用短答复反例防止模板化。

## Risks / Trade-offs

- [检查点模板化] → 只有会阻塞测试推进或需要结果回填的人工步骤建立检查点；短请求直接提问或说明操作。
- [人工结果造假或误读] → 记录回填人、时间、原始证据和观察边界；不把口述概括写成原始观察。
- [术语层膨胀] → 每个术语一句定义或指针；方法细节不复制。
- [检查点残留] → 每次新会话或阶段交接恢复状态；失败/取消/放弃显式记录原因。
- [静态检查无法证明行为] → 契约测试只覆盖字段和引用，行为用真实模型评测验证。

## Migration Plan

1. 扩展 `running-test-sessions` 的人工检查点契约。
2. 扩展 `test-privateer` 的阶段边界与恢复规则。
3. 扩展 `artifact-routing` 的领域语言层。
4. 增加静态契约和评测输入。
5. 运行验证；实施后保留活动 change 等待用户确认。
