# Proposal

## Why

当前测试执行链对“只能由人完成的步骤”已有授权边界，但缺少统一检查点契约。无环境访问权时，Agent 可能只给出口头等待或零散指导，导致负责人、操作入口、成功观察、失败证据、回填位置和恢复动作丢失。新会话继续时，也难以判断人工步骤是否完成以及结果是否可信。

同时，测试领域语言已有基础：`artifact-routing` 定义了术语、编号、handoff 和 TCO；主入口新增了词汇与资产层。但 SFDIPOT、MFQ、PPDCS、charter、probe、oracle 等方法语言仍分散在专项 Skill 中，缺少一个轻量、单一权威的领域语言入口，容易出现“测试点／测试项／测试条件”等同义词漂移。

## What Changes

- 为 `running-test-sessions` 增加人工检查点契约：
  - 触发条件：Agent 无访问权、平台限制、安全边界、只有人可完成的配置、审批、第三方后台操作或不可自动化观察；
  - 检查点字段：负责人、目标、系统/页面/凭据入口、前置状态、操作、成功观察、失败保留证据、超时/放弃条件、结果回填位置、恢复下一动作；
  - 状态机：待确认/待执行/执行中/已完成/失败/取消；
  - 人工返回的截图、值或结论作为原始观察，不冒充 Agent 亲自执行。
- `test-privateer` 主入口在阶段边界中加入人工检查点：
  - 生成或确认检查点；
  - 新会话先恢复未完成检查点；
  - 结果未回填前不推进依赖该步骤的测试链。
- 扩展 `artifact-routing` 的测试领域语言层：
  - 保持术语唯一权威；
  - 补齐测试项、测试条件、探索章程、探查、判定依据、测试发现等核心术语边界；
  - SFDIPOT、MFQ、PPDCS 保留原名，并在领域语言层给出轻量定位和方法 Skill 指针；
  - 明确同义词归并规则，不在专项 Skill 中重复维护定义。
- 增加最小静态契约和代表性行为评测输入：
  - 人工检查点；
  - 人工结果回填后恢复；
  - 术语漂移纠正；
  - 短答复不强制术语表。

## Capabilities

### Modified Capabilities

- `testing-workflow`: 主线和执行阶段支持人工检查点的创建、恢复、回填和授权边界。
- `test-artifact-quality`: 领域语言层保持唯一权威，术语在测试产物中一致且按需解释。

## Impact

- 修改：
  - `skills/running-test-sessions/SKILL.md`
  - `skills/test-privateer/SKILL.md`
  - `skills/test-privateer/references/artifact-routing.md`
- 新增测试或契约检查。
- 新增代表性行为评测输入。
- 不新增 Skill。
- 不实现通用交互脚本生成器、外部审批系统或自动 UI 操作。
- 不把所有人工动作都编号；仅需要等待、回填或恢复的步骤建立检查点。
