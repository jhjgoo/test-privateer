# Design

## Decisions

1. **共享参考放在 `reviewing-ui-ux`。** MWG 的主要价值是提供现代 Web 平台依据和候选发现，与 UI 评审的“适用依据 + 证据边界”最接近；自动化设计只在 Web 界面方法选择时读取它。
2. **引用而不复制。** 保留上游 GitHub 链接和 CLI 用法，本仓库只维护测试语境下的证据边界，避免指南漂移和内容重复。
3. **扫描输出降级为候选。** `legacy-scan` 可以定位旧写法，但只有结合指南验证规则、真实渲染／操作和产品承诺后，才能成为发现或修改建议。
4. **现代化审计复用现有入口。** UI 评审负责判断和证据，自动化设计负责测试方法与 Harness；不新建第四个入口。

## Risks / Trade-offs

- CLI 依赖网络和执行授权；未授权时参考仍要求引用用户提供的指南或报告。
- 静态扫描存在误报和漏报，报告必须保留候选、不适用、证据不足和未覆盖分类。
- 自动化入口直接跨 Skill 引用共享参考，已有跨 Skill 相对链接模式支持该用法。
