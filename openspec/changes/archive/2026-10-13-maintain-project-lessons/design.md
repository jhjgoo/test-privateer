# Design

## Context

现有调查、方案质检和回归技能已承接取证与验证。本变更把教训维护放在它们之后或独立整理时调用，需求见 proposal；当前工作区干净，无活动 change 可复用。

## Goals / Non-Goals

交付一个无需联网执行的通用维护 Skill，适用于代码、测试、Prompt 和 Agent 工作中的返工。方法来自指定参考，案例与技术栈不成为使用方规范；只引导材料整理，不实现自动审计器。

## Decisions

- 选择一个 Skill 的“记录／整理／提炼”分支，而非两个相互依赖的 Skill；共同证据链只维护一次。主文放决策与完成条件，参考放模板、判据和来源解释。
- 复用项目路径；按用户补充要求，没有特殊约定时采用项目根目录 `LESSONS.md`，长期规则直接写入根目录 `AGENTS.md` 并保留原内容。已有独立规范时继续沿用并使用入口短指针。不把整份错题本注入每轮上下文，也不强制 OpenSpec。
- 采用独立事件计数。Magpie 的三个不同审查日是可配置候选标准；单个事故被多日重复看到仍须标明其去重关系。重大单次事件依据已确认约束另行判断。
- 规则只保留一个权威定义，晋升后的教训保留证据与链接；失效项标明原因与替代位置。历史连续水位仅越过完整读取范围，稀疏覆盖单列。
- 验证使用同一固定场景的无技能基线与带技能执行、邻近正常和材料缺失场景。独立上下文由 writing-skills 的行为验证流程要求，不委派实现。原始输出留 `.local/validation/`，输入与判据跟踪。

基线四例全部通过，不存在本次观察到的基线失败，故本变更按用户要求将方法打包，不声称修正了已证明的模型缺陷或带来量化提升。两组四例各共用一个子 Agent 上下文，此限制随结果保留。独立审阅指出文字场景不能验证实际维护，已补充临时文件夹具的授权维护分支；该分支独立执行，不加入前后效果比较。

## Risks / Trade-offs

- 从案例抽取过度泛化 → 要求适用条件、正常反例和可区分检查，外部约定只作为方法来源。
- 用新增文档代替真正修复 → 教训保留问题状态；原因、验证和规则落实分别说明。
- 文档堆积与全局修改 → 复用权威位置、最小入口指针、按授权维护；不安装全局 Skill，不发外部消息。
- 小样本被夸大为稳定效果 → 仅报告实际场景输出，不声称模型或宿主普遍有效；基线通过同样保留。

## Migration Plan

新增 Skill 并同步主入口和教程，全集数量更新为 26。已有安装者按 README 重新安装全集取得新组件。可逆回退为移除新入口及新增 Skill；已有调查与测试路由不变。

用户于 2026-10-13 明确要求完成须经确认，归档不得自动执行。此前本轮已执行归档，现恢复同一活动 change，并将提前同步的新规格保留到本地验证记录；新能力契约仍由本 change 的 delta 承载。实现与既有验证保留，当前状态为待用户确认。AGENTS.md、project.md 与 config.yaml 已写入确认条件，当前仓库流程规格的更新作为同一 change 的 delta，待用户确认后再同步。

## Project Lesson Initialization

用户授权用新 Skill 建立本项目错题本与规则约束。根 LESSONS.md 记录本次归档恢复、评测设计缺口与历史表达优化中的模板／入口不一致、精简损失；直接记录与历史回填分别标明来源。AGENTS.md 保留既有内容，增加相关教训读取指针，并按共享消费链、可观察验证、语义保真和证据边界归并已有或证据支持的要求。CLAUDE.md 继续通过既有 `@AGENTS.md` 引用接入，不复制规则。

本轮使用有限材料集合，不设置连续 reviewed-through 水位、不审核全部 Git 历史。每条教训仅记一个可识别事件，多个补丁与意见不重复统计；用户确认的约束及已有规格直接落实，不为晋升门槛虚构三次事故。维护完成只证明文档和关联入口建立，后续 Agent 是否遵循尚无新行为证据。验证核对事件来源、状态、语义、链接、既有规则保持以及 change 待确认状态，不另建审计平台。
