# Proposal

## Why

现有测试资产能管理项目地图、需求分析、用例和单次执行记录，但缺少跨阶段测试轮次的统一身份、状态和证据适用性。完整测试 Loop 若直接建立在零散 handoff 上，容易混用旧结果、覆盖历史记录，或在暂停恢复后失去授权与退出条件。

## What Changes

- 为多阶段、跨会话、并行执行或明确要求审计的测试建立稳定 Run ID 和唯一轮次记录。
- 区分轮次状态、单项测试判定和测试信心结论，禁止用“轮次已完成”表示“测试通过”。
- 让轮次记录只索引现有 TCO、测试分析、用例、执行证据和报告，不复制这些资产的正文。
- 定义原始证据的身份、适用版本、环境、来源、敏感性、保留期限和失效边界。
- 定义资产因规则、版本、环境、夹具或验证器变化而需要复核或被替代时的处理方式。
- 让人工检查点、暂停恢复点和追加式决策日志引用同一轮次边界。
- 保持短小、单次且方向不变的测试任务轻量，不强制创建轮次资产。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `testing-workflow`: 增加可恢复的测试轮次身份、流程状态、单一合成者和关闭边界。
- `test-artifact-quality`: 增加证据身份、适用范围、敏感性、保留与资产失效要求。

## Impact

- 共享资产规则和模板会增加测试轮次记录，但不会改变 TCO、需求分析和用例的权威归属。
- `running-test-sessions`、`assessing-test-confidence` 和 `selecting-regression-tests` 将读写同一个 Run ID。
- 新增契约测试和最小行为评测，验证短任务不被强制扩写，长任务可以恢复且不会混用历史证据。
- 本 change 不新增公开 Skill，不配置项目环境，也不编排完整 Test Loop。
