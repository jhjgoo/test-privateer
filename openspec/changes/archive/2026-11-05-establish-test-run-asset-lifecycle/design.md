# Design

## Context

当前资产体系以 `testing/TCO.md`、需求测试分析、测试依据和测试用例为权威来源。`running-test-sessions` 已提供人工检查点、暂停恢复和追加式决策日志，但这些记录没有共同的轮次身份。`assessing-test-confidence` 可以汇总证据，却没有统一入口判断证据是否属于本轮、是否过期或是否在清理后仍可访问。

本 change 为后续项目 Setup 和 Test Loop 提供共享契约。它不引入新的公开 Skill，也不替换现有资产。

## Goals / Non-Goals

**Goals:**

- 为需要协调的测试工作建立一个轻量轮次记录。
- 让轮次状态、测试判定和信心结论各有一个权威位置。
- 让证据可以按 Run ID、测试对象、版本和环境定位。
- 保留旧执行记录，并明确当前资产何时需要复核。
- 支持并行取证，但只允许一个合成者修改共享资产。

**Non-Goals:**

- 不为每个短测试创建目录或状态文件。
- 不规定所有项目必须把截图、视频和日志提交到 Git。
- 不创建外部测试管理平台、缺陷平台或对象存储集成。
- 不编排完整 Test Loop，也不配置项目测试环境。

## Decisions

### 1. 使用一个轮次记录作为索引

默认路径为 `testing/runs/<run-id>/run.md`。Run ID 使用 `RUN-<YYYYMMDD>-<NNN>`，序号在当前项目和日期内递增。项目配置可以指定其他根目录，但不能改变 Run ID 的稳定身份。

轮次记录只保存以下内容：

- 测试对象、目标版本或快照和触发来源。
- 范围、授权、禁止动作、预算和退出条件。
- 当前阶段、轮次状态、阻塞和下一动作。
- TCO、分析、依据、用例、证据和报告的指针。
- 人工检查点、恢复点和决策日志的最新边界。

TCO、用例、证据和报告继续在各自权威位置维护。轮次记录不复制正文。

替代方案是把全部状态写入测试用例文件。该方案会让跨需求、跨测试层级和未进入用例阶段的工作无处记录，因此不采用。

### 2. 轮次记录只用于需要协调的任务

以下任一条件成立时创建轮次记录：

- 请求包含分析、用例、执行或报告中的多个阶段。
- 任务跨会话、需要暂停恢复或包含人工检查点。
- 多个 Agent 或执行分支参与。
- 用户明确要求审计。

单次、单项且方向不变的测试继续使用现有执行记录。`artifact-routing.md` 维护这一门槛，避免模板扩散。

### 3. 使用一个流程状态，而不是多个互相依赖的标记

轮次状态只允许：

```text
准备中 → 可执行 → 执行中 → 已完成
                    ↘ 已暂停
                    ↘ 受阻
任意未完成状态 → 已取消
```

已暂停和受阻可以恢复到执行中。已完成和已取消保持历史身份。后续产品执行创建新 Run ID。

测试判定继续使用通过、失败、跳过、受阻和待判定。测试信心继续由 `assessing-test-confidence` 维护。三类状态不能互相替代。

### 4. 在轮次记录中维护证据索引，不移动所有证据

轮次记录的证据索引包含：

- 证据指针。
- 关联测试或 Finding ID。
- 目标版本、环境、时间和来源。
- 原始证据或摘要。
- 敏感性和访问边界。
- 保留期限或已知失效条件。

项目已有 CI Artifact、测试平台或对象存储时继续使用。没有长期位置时，Agent 记录本地路径和可复核性限制。Setup change 后续可以提供项目默认策略。

### 5. 用“当前有效、需要复核、已被替代”描述资产适用性

资产适用性不是执行结果。规则、版本、接口、夹具、环境权限或验证器发生相关变化时，Agent 在权威资产或轮次索引中更新适用性，并保留原执行记录。

不增加更复杂的审批状态。现有风险、Case 和 Finding 已有各自状态，再增加一套完整资产工作流会产生重复。

### 6. 并行分支只返回结果，由一个合成者写共享资产

主调用方是轮次合成者。分支 Agent 只写各自隔离的证据，或返回证据路径和 handoff。合成者更新 `run.md`、需求分析、用例和报告。

共享账号、数据、端口或会话无法隔离时改为串行。第一版不实现文件锁。

### 7. 通过契约测试和行为评测验证边界

静态测试检查：

- 轮次模板包含必要字段。
- 短任务例外仍存在。
- 轮次状态、测试判定和信心结论没有混写。
- 证据索引包含版本、环境、来源、敏感性和保留边界。
- `running-test-sessions`、`assessing-test-confidence` 和 `selecting-regression-tests` 引用同一 Run ID。

真实模型行为评测至少覆盖长任务建档、短任务不建档、暂停恢复、旧报告残留、敏感证据和并行分支归并。原始输出和加载轨迹保存在 `.local/validation/`。

## Risks / Trade-offs

- [轮次记录变成重复报告] → 模板只允许状态和指针，禁止复制分析、用例和证据正文。
- [项目不希望跟踪运行目录] → 项目配置可以选择其他位置；没有配置时只对需要协调的任务使用默认路径。
- [人工修改破坏状态一致性] → 合成者在恢复和关闭前回读轮次记录及其资产指针。
- [外部证据过期] → 记录保留期限和限制；报告不把过期链接当作可复核证据。
- [并行分支覆盖共享文件] → 明确单一合成者，分支只返回隔离证据和 handoff。

## Migration Plan

1. 增加轮次模板和共享资产规则。
2. 让执行、回归和信心评估读取可选 Run ID。
3. 对新产生且满足门槛的任务创建轮次记录。
4. 保留现有 TCO、分析、用例和历史执行记录，不批量迁移旧资产。
5. 若回滚，停止创建新轮次记录；现有 `run.md` 仍作为只读索引，不影响原资产。
