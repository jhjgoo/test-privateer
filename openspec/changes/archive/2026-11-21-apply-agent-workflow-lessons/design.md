# Design

## Decisions

1. **共同契约放在 `running-test-loop/references/`。** 只有完整 Loop 的冷启动盲测使用它；普通单层测试不新增必读步骤。
2. **错题本只加筛选条件。** 不改变证据字段、统计口径、权威位置和晋升流程；pstack 的 reflect 轻量化不替代本仓库的真实事件要求。
3. **方案质检只加一个结构信号。** 重复特判是线索，不是缺陷本身；仍需检查规则依据和边界后再判断。
4. **测试表面隐藏执行 nuance。** 可固化的准备、驱动、观察和判定信息进入 Case 字段、脚本、测试标识或断言；只有专业判断保留为人工检查，不写成隐式经验要求。
5. **任务包生成也读取共同入口。** 2026-11-21 实测发现 GLM 新版虽引用共同契约，仍在两份 brief 重复证据、写入和 handoff 规则，官方评分未识别。编排者改为先读共同契约中的任务包骨架，只填本轮差异；骨架保留身份、前置、入口和隔离输出，不以删掉必要条件换取短文本。原失败保留，Loop 单独补跑旧版／修正后对照。
6. **缺少实现细节不推定合法分支有缺陷。** 同轮匿名答案复核发现 GLM 新版额外发明法规日期选择链要求，误报已确认的地区规则。方案质检补清已确认事实与未知实现的边界：没有具体冲突或失败证据，只列未验证，不增造适用条件或 finding。用原冻结的目标／正常组合案例单独补跑旧版／修正后对照。
7. **交付身份与通用规则分开承载。** Loop 首次修正后的 GPT 将“主会话是唯一合成者”和通用写入禁令一起塞进“本轮专有交付”。先将该混合字段拆成接收者身份与可省略的附加产物；后续 `loop-cli-contract` 的 GLM 仍把共同 handoff／证据规则塞入附加产物，而原需求没有独立附加产物场景，因此删除该可选入口，只保留唯一合成者和隔离输出，不用文本提醒继续承载可绕过的 nuance。
8. **单独准备任务包有明确入口。** 此前修正假设“执行章节中的编排者指令能让仅准备任务包的会话读取共同契约”；`loop-final` 的 GLM 轨迹读取了主 Skill 却未读取该引用，直接输出另一套任务格式，反驳了这一前提。把仅准备任务包分支放在启动契约之前，直接路由到共同契约并在交付后停止，不让准备任务穿过完整 Loop 的就绪／执行条件。读取审计保留在本地 `reference-read-audit.json`；不以文件存在证明接入成功。
9. **结构和路径由生成器负责。** `loop-entry` 的 GLM 已读取共同契约，但仍把通用写入禁令放进前置字段，并生成相对位置错误的引用；单靠模板和提醒仍未收敛。使用 Python 标准库脚本接收已确认的任务差异，固定正文结构、按任务文件位置计算引用，不执行获准测试命令；支持命令及非命令入口和专有前置，拒绝多行字段、工作区外写入及覆盖不同旧内容。删除临时模板，仅保留原共同契约。临时目录测试核对路径、原文件保持、幂等和没有实际测试副作用；行为回归继续用原冻结题目，不将脚本调用写成唯一正确答案。
10. **CLI 使用明确的领域角色。** 实测两模型把泛称的 recipient 理解为执行者，故参数改为 `--synthesizer`，帮助文本明确它是接收 handoff 的唯一合成者。独立审查另发现未规范化父路径可能在工作区外创建中间目录；真实临时目录反例先失败，再统一使用已解析路径创建和写入后通过。提示词、脚本、测试和调用方一同更新，不保留未发布的旧参数别名。

## Risks / Trade-offs

- worker 指针不能证明子代理实际读取；仍依赖任务包、调度轨迹和隔离 handoff 审计。
- 过严筛选可能丢弃高后果单次教训；已有“项目已确认高后果约束可单次晋升”规则继续优先。
- “反复”没有固定次数阈值，按同一边界和机制判断，避免机械规则误报。
