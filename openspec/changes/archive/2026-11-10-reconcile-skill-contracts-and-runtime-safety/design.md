# Design

## Context

本方案承接 2026-11-10 的全包审计。审计读取了 30 个 Skill、24 个参考／模板、2 个随包脚本及主入口，基线提交为 `bc05406890127232a15211f2bf014a162ad72a85`，并包含工作区已实施的生命周期改动。提交号不能单独代表本次受审内容；本轮审计的文件哈希保存在本地 `snapshot.json`。

审计时配置并发回滚、XMind 内容丢失、安装后脚本路径和失效路由检查已有临时夹具复现；其余问题来自同一条件下的规则对照，当时尚无本 change 的真实模型修复证据。此前 81 项测试及包检查通过，不代表上述反例已覆盖。本次实施结果见末尾验收记录。

本地证据位于 `.local/validation/all-skills-audit-20261110/`，不纳入分发包。下面保留可独立复现的问题与验收目标；实施不依赖本地记录始终存在。

## Goals / Non-Goals

**Goals**

- 修复已确认的内容损失和无效检查，再统一同一任务在不同入口下的授权、选型与完成条件。
- 在原有规则、脚本和专项中修正，沿实际消费者更新引用、模板、测试与评测判据。
- 用文件动作及自然任务结果验收，不以规则关键词、标题或模型自述替代证据。

**Non-Goals**

- 不新增 Skill、测试框架、通用 Markdown 解析库、状态服务、全局自动钩子或固定决策卡。
- 不增加配置 v3、长期状态枚举或另一份 Run／进度账本；不批量改写使用方项目。
- 不启动验证器生成交接，不归档其他 change，不将规划写成已完成整改。

## Decisions

### 1. 配置先校验候选，再发布；冲突时保护现有内容

保留项目根目录、标记、符号链接、换行、权限与人工区保护。将当前在正式目标上执行的 `after_write` 调整改为明确处理暂存候选的回调；实施时采用 `prepare_candidate` 命名，迁移 Setup 说明及仓库内全部调用者，不新增 CLI 配置项。当前生产 CLI 不传回调，Python 调用和测试需要迁移。

候选在同目录临时文件中构造；必要后处理、内容和权限检查通过后，再复核正式目标的存在性、内容、身份及位置。目标与初始快照不同就报告写入冲突，清理本次暂存文件，不覆盖正式目标。候选处理失败时原文件尚未改变，首次创建也不留下无效配置。

发布后仍回读；若不能确认差异属于本次操作，不无条件还原旧快照或删除目标。保留现状，报告未完成部分和人工核对入口，不虚称事务成功。只能作用于正式路径或修改其他文件的后处理器，不纳入这一单文件写入契约；没有安全暂存方式时停止该写入并说明原因。

这是移除破坏性恢复路径，不是通用并发事务：提交前比较与原子替换之间仍存在外部编辑竞态。合作调用者应串行写入；本 change 不构建跨编辑器锁服务，也不声称对未协调写入者提供完整隔离。

### 2. XMind 保真优先于宽泛格式承诺

明确支持的 Markdown 子集；保留路径、正则和转义文本，仅处理表格分隔所需的明确转义。标题加详情输入先按既有编号归一化为完整可转换结构；若无法无损转换，列出具体位置并停止成功交付，不静默丢弃正文、缺列行或无法解析的 Case。

跳过规则覆盖整个章节及其表格，直到相同或更高层级的新章节。导出不改权威源文档；验收比较编号、准备、步骤、预期、来源与层级，并检查应排除的历史内容。复用脚本和标准库 ZIP/XML/JSON 检查，不引入通用 Markdown 引擎。

### 3. 执行授权、实际验证、项目采纳各自判断

在 `harness-readiness.md` 维护唯一规则，专项只保留调用说明：

- 当前授权允许临时驱动生成与运行时，可以在指定范围试验；“AI 生成／临时／未提交”本身不是禁令。
- 执行结果由真实 Drive、证据与恢复结果支持，不因授权或脚本存在而成立。
- 项目长期入口需要权威来源或明确采纳决定。一次试验通过不自动写入长期 `verified`；已有六种 Harness 状态保持不变。

未知历史脚本没有可信来源或执行授权时仍不可自动运行。只要求设计／编写的任务保持未执行。产品代码、环境、网络、费用和数据边界沿用既有授权规则。

### 4. 单元测试用两个维度决定完成条件

| 请求范围 | 新行为／缺陷保护 | 既有行为保护 |
| --- | --- | --- |
| 设计 | 给出真实 seam、输入输出、oracle 和预期失败原因；不声称实际 RED | 给出当前行为依据、边界与判据；不运行 |
| 只编写 | 交付可用测试与执行入口，明确未运行 | 同左，不强制制造失败 |
| 编写并验证 | 实际运行目标测试；应失败时确认业务性 RED，首轮 GREEN 时调查原因 | 允许真实首轮 GREEN，检查断言及目标行为，不故意破坏产品来制造 RED |

RED 属于相应 TDD 阶段的退出依据，不等于整个开发任务完成。最终结论按实际失败、通过或受阻报告；该 Skill 不因此获得修改产品实现的权限。

### 5. 跨入口只使用一条实质选型规则

优先沿用适用的权威项目入口；用户指定或明确委托选型时在边界内执行。无委托且选择引入实质长期依赖、维护方式、费用或执行边界时，说明影响后确认。既有栈内选择客户端或标准库临时探针，不自动升级成长期框架决策，不强制先跑完整 Setup。

选型委托不等于安装、联网、付费或替换已有套件授权。DeepEval 官方 Skill 安装仍走既有明确确认边界。把这条规则放入现有 Harness 参考，Setup、API、E2E 和自动化在相关分支按需读取，不能仅添加不可达文件。

### 6. 状态按对象命名；交接按来源携带许可

项目配置继续使用四种 Setup 状态；`awaiting_install_confirmation` 只表示当前宿主所需官方 Skill 的待确认状态，不写入项目长期枚举，也不是评测失败。拒绝或确认后仍不可用，才按既有协议记录对应的能力缺口；“没有询问结果”不与拒绝同义。

共享交接中的执行许可改为已授权动作、边界及来源；进度继续放已有的完成／未完成信息，不增新状态表。旧交接写“执行中／已完成”时只解释为进度，必须回查原始授权，不能由进度推导写文件、启动服务或运行测试权限。

### 7. 修正表达、发现入口与安装路径

- 评测盲测隔离隐藏判据、答案、预期缺陷及候选身份；真实任务中的 `test-privateer`、`tests/`、业务 score 字段可正常出现。匿名比较与实际加载证据要求不变。
- MFQ 摘要指向专项的单个有界功能定义；SFDIPOT 按实际 PRD、原型、访谈或运行证据标注视角和未知，不编造来源。
- 自动化 description 覆盖既有方法选择、Harness／验证器生成和维护。用仅暴露名称及描述的自然任务检查发现，再核对实际加载，禁止直接注入目标 Skill 冒充发现成功。
- 脚本和必需参考相对实际加载的 Skill 目录解析。仓库研究文档不是安装后必读条件；在现有参考中保留执行所需摘要及可选来源，不把整个研究库打包。全局安装、项目安装和仓库内使用都从无关工作目录验证。

### 8. 包检查必须真正观察路由

修改现有解析器，使其识别当前路由结构；无法找到或提取有效路由时失败，不能以空集合通过。核对每个目标 Skill 存在，错误定位到主入口和缺失名称。继续沿用路由表作为来源，不添加第二份手工路由清单，也不扩成通用 Markdown 检查器。

## Change boundaries and rollout

| change | 本次关系 |
| --- | --- |
| `connect-test-assets-to-development-lifecycle` | 作为已实施集成基线；保留完成触发、局部纠错和来源维护。不修改其产物或验收记录；本 change 的配置写入安全等是审计后的独立整改 |
| `add-setup-project-verifier-handoff` | 仍未实施；缺少验证器时的确认／生成交接归该 change。本次只消解既有方法的授权、采纳和发现问题 |

当前方案 delta 不与两个活动 change 修改同名 Requirement。实施及归档前重新核对三方规格，不能覆盖另一 change 新增行为；若基线改变，先更新本 change 的设计与任务。

实施顺序：① A11 使检查有效，A01/A02/A10 保护工具与交付；② A03/A04/A06 统一执行契约；③ A05/A07/A08/A09 校准状态、术语和发现；④ 集成行为评测。每步复用原消费者和测试，不把方法定义复制到全包。

CLI 参数与现有配置路径保持不变；Python 回调迁移在同一次实施中完成。直接使用旧 `after_write` 的包外调用者需要迁移到暂存候选语义，发布说明须写明这一变化，不保留会暗示正式文件已更新的旧别名。旧项目配置不自动重写；只在正常任务需要时按来源解释和校准。Skill 安装同步、规格同步、归档、提交和推送均不属于本次实施交付。

## Validation strategy

| 组 | 必须观察的反例及通过条件 | 证据方式／覆盖 |
| --- | --- | --- |
| V1 配置安全 | 候选抛错、删候选、改权限、改变正式目标、初次创建被他人抢先写入；无非本次内容被回滚／删除 | 临时复制品、屏障控制的独立写入者、字节／权限／路径比较；A01 |
| V2 转换与安装 | Windows 路径、正则、字面反斜杠、转义竖线、标题正文、历史附录、异常行；输出保真或明确拒绝，源不变 | ZIP 内容断言、源码／全局／项目安装及无关 cwd；A02/A10 |
| V3 包完整性 | 当前正常路由通过；缺失目标、空路由、过期结构定位失败 | 临时完整包负例，检查非零退出和具体错误；A11 |
| V4 执行分支 | 获准临时试验可运行但不长期采纳；历史脚本不得擅自运行；单元设计、只编写、首轮 GREEN、有效 RED 分别完成 | 自然任务、实际命令和文件差异，禁止修改产品；A03/A04 |
| V5 选型一致 | 无委托有实质影响时询问；明确委托、既有栈、标准库探针不重复阻塞；选择不等于安装授权 | Setup/API/E2E/自动化入口成对任务及实际读取记录；A06 |
| V6 状态与交接 | 项目可配置但宿主缺官方 Skill；等待／拒绝／确认后不可用分开；旧“已完成”记录不产生新执行权限 | 适配现有就绪与恢复场景，核对文件状态与工具动作；A07 |
| V7 语言与发现 | 自然 test/score 名称不删；隐藏判据不泄漏；MFQ 摘要保留有界功能含义；非 PRD 来源不冒充 PRD；验证器生成与维护可从元数据发现 | 盲测材料边界检查、自然输出与真实加载轨迹；A05/A08/A09 |

先把确定性反例固化为行为测试，保证当前错误实现能够失败；不新增只查规则字符串的测试代替行为。同步审查既有字符串契约测试，保留必要结构检查但避免与实现互相复述。

真实模型评测复用 `evals/project-test-setup/`、`evals/test-harness/`、`evals/test-loop/`、`evals/agent-eval/` 和相关现有套件，按任务就近放输入与判据，不另建总控框架。每场独立临时项目及当前 Skill 快照，自然任务可见、判据不可见；框架／宿主操作用受控替身或已有安全入口，不进行真实安装、上传或付费调用。

记录实际 CLI／模型／推理与权限配置、提示、完整输出、加载与工具轨迹、文件差异及前后哈希、退出状态、耗时；区分 `pass`、`agent_failure`、`environment_error`、`invalid_case`。原始记录留在 `.local/validation/`，可复用夹具和判据跟踪。对关键授权与恢复边界复跑，修订后重跑失败及受影响场景，旧尝试不删除。只有同协议基线／候选证据支持时才声称改善，双方均通过不等于提升。

最终运行全量 unittest、包检查、XMind 自检、活动 change 及全部规格严格校验、`git diff --check`。保留失败和未执行项；有限样本通过不声称所有模型稳定。

## Review gate

阶段为用户确认后的归档。A01—A11 已落入原专项、共享参考、随包工具与消费者，未新增 Skill 或长期状态值。用户于2026-11-10确认完成后，已同步6份当前规格并归档；12个有差异的本地Skill已更新，全包30个安装目录的有效文件哈希与仓库一致。任务勾选本身不是归档授权，本次按用户明确确认执行。

实施前文档自校保留：2026-11-10，本 change 与全量 OpenSpec 严格校验通过（15/15）；13 条 MODIFIED 保留原有场景标题，6 条 ADDED 不与当前规格重名；与另外两个活动 change 无同名 Requirement 交叠。该记录只说明当时方案结构有效。
