# Proposal

## Why

全包审计发现 11 项工具与行为契约问题：配置回滚和脑图转换可能丢失内容，路由检查未覆盖实际路由表，部分专项把授权、采纳、进度和完成条件混在一起。需要统一修正这些共同边界，并用实际文件动作和自然任务评测验收，降低后续调用中的误执行、误阻塞和失真交付。

## What Changes

- 保护配置写入与失败恢复中的人工／并发内容；回读失败不能无条件覆盖其他写入者的变更（A01）。
- 修复 XMind 转义、正文归一化和跳过章节的保真边界；安装后按 Skill 真实位置调用脚本（A02、A10）。
- 将本轮执行授权、Harness 实际验证与长期项目采纳分开；统一普通 Setup、API、E2E 和自动化专项的实质选型边界（A03、A06）。
- 单元测试按设计、只编写、编写并验证验收；有效 RED 仅约束对应的新行为／缺陷保护分支（A04）。
- 按内容是否泄漏隐藏判据判断评测污染，允许真实任务词和 Skill 原名；保持盲测隔离、匿名比较和真实加载轨迹（A05）。
- 区分项目配置状态、当前宿主官方 Skill 就绪状态和阶段交接中的授权／进度；不增加长期状态枚举（A07）。
- 校准 MFQ 摘要和扫描证据来源，补齐 Harness／验证器的入口描述，消除安装包外的必读路径（A08—A10）。
- 让包检查器验证当前路由表；路由未提取、目标缺失或解析结构失效必须显式失败（A11）。

实施优先替换冲突条款，不新增 Skill、总控提示词、状态服务、固定决策卡或测试框架。实际结果与保留边界见 design 的验收记录和 tasks；实施完成后仍保留活动 change，等待用户明确确认。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-test-setup`：配置安全恢复、实质选型委托和宿主／项目状态区分。
- `test-automation`：执行与长期采纳、单元测试分支、跨入口选型的统一边界。
- `test-artifact-quality`：导出保真、按分支保留单元证据、方法定义及来源准确性。
- `testing-workflow`：自然任务与评测泄漏、授权交接、入口发现和官方 Skill 状态。
- `deepeval-agent-evaluation`：等待确认不算实施失败，官方 Skill 状态仅描述当前宿主。
- `skill-package-integrity`：有效路由检查与安装后的运行资源可达性。

## Impact

作用于现有 Setup、自动化／单元／API／E2E、Agent／DeepEval、SFDIPOT、XMind 及主入口的相关规则和引用；涉及两个随包脚本、包检查器、契约测试及现有行为评测套件。详见 design 中的 A01—A11 作用点和验收矩阵。

以已实施但未归档的 `connect-test-assets-to-development-lifecycle` 为集成基线，保留其维护触发、证据边界和未决字段纠错能力。本 change 独立承接审计后的整改，不重新定义该 change 的维护机制，也不修改其验收记录。`add-setup-project-verifier-handoff` 继续只负责 Setup 到验证器的确认与交接，本 change 不启用该功能。

保持现有 30 个 Skill 名称、项目配置 v2、长期状态值和现有 Run ID。写入器内部回调可能改为处理暂存文件，属于需迁移全部本仓库调用者的操作契约变化；不承诺未协调外部写入的全局原子事务。未获明确确认前不归档、同步当前规格或安装副本。
