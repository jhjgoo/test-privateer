# Proposal

## Why

真实 Setup 使用把“何时验证”与“指定技术入口”混成选择，且直接调用未实际读取共享表达。后续开发更新了任务与证据，项目配置和 TCO 中复制的短期进度却没有同步；需要接通开发收尾责任，而不是加重问卷或反复重跑 Setup。

## What Changes

- Setup 直接读取共享表达；确认问题围绕同一决策、必要事实和后果，不新增固定决策卡。
- 长期配置与 TCO 不复制任务勾选数量和单轮待办，保留来源、适用版本及项目级认知。
- Setup 在项目实际加载的协作入口接入最小收尾约定，复用已有等效规则，保留人工内容；不能接入时如实报告部分完成。
- 开发交付、验证交付和归档后按影响维护配置、TCO 与迁移指针；无影响不改，历史证据不覆盖。
- 增加直接 Setup、新会话开发、归档与无关改动行为评测，核对真实读取及文件变化。
- 根据实际使用反证补齐混合安装目标内容核验、旧资产定向追证、最终问题自校及协作流程豁免判断；增加陈旧配置与相邻正常样本，避免静态文件检查代替行为验收。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-test-setup`：初始化同时建立可读取的开发收尾联动，受现有项目规则和用户范围约束。
- `test-artifact-quality`：用户决策表达与长期资产的单一状态归属。
- `testing-workflow`：开发／验证交付和归档时按影响更新测试资产。

## Impact

作用于 Setup、主入口、共享参考、TCO／配置模板及测试交付的引用指针；补充教程、评测材料和必要契约检查。不改第三方 dev Skills，不安装钩子，不引入状态服务，不替使用方项目修补本次历史产物。与 `add-setup-project-verifier-handoff` 的验证器生成交接保持独立。
