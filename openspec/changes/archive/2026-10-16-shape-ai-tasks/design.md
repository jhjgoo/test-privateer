# Design

## Context

见 `proposal.md`。当前 `test-privateer` 已负责测试阶段路由，`setting-test-mission` 负责测试使命，`clarifying-test-basis` 负责产品事实和 oracle；本变更只增加它们之前的任务升级边界。

## Goals / Non-Goals

**Goals:**

- 用一个独立 Skill 识别低层级或不完整请求，并生成可执行任务契约。
- 保持明确请求的短路径，避免所有请求都进入问卷。
- 让“高度、深度、范围、验证”成为路由前检查，并把专家方法落到材料、动作和验证上。
- 用静态契约和代表性输入验证入口、边界与交回关系。

**Non-Goals:**

- 不建立通用 Prompt 模板市场、多 Agent 编排或自动评分器。
- 不替代测试使命、测试依据澄清、风险分析、方案质检或执行授权。
- 不修改安装方式、工具权限或用户项目。

## Decisions

1. **新增独立 `shaping-ai-tasks`。** 任务升级横跨测试、Prompt、方案和 Agent 请求，放入 `test-privateer` 会扩大主入口职责；独立 Skill 也便于单独评测。
2. **采用条件式触发。** 只有目标、交付物、成功信号或验证缺口会改变路线时才介入。明确请求直接进入既有专项，避免增加延迟和重复澄清。
3. **输出任务契约而非只输出改写 Prompt。** 契约同时保留目标、材料、方法、权限、验证和未决项，便于下游路由和证据边界检查。
4. **在主入口只增加一条上游路由。** `test-privateer` 增加任务升级判断和路由表条目，具体方法留在新 Skill，避免复制规则。
5. **评测采用输入与判据，不新增运行器。** 新增需要升级、明确放行、只缺 oracle、需要原始材料和跨领域方法的最小输入；契约测试检查入口和评测资产，真实模型运行按现有评测协议另行记录。

## Risks / Trade-offs

- [过度澄清] 新 Skill 可能把简单请求变成问卷 → 明确请求设置直接放行场景，并要求每轮最多追问会改变方向的关键问题。
- [目标臆测] AI 可能把推荐目标写成用户决定 → 明确区分事实、推断、推荐和待确认项。
- [方法堆砌] AI 可能罗列专家领域但不产生新证据 → 要求每个方法说明动作、材料和会改变的判断；没有认知增量时不引入。
- [路由回退] 主入口可能重复调用任务升级和测试依据澄清 → 在新 Skill 与主入口中固定边界案例，并加入契约断言。

## Migration Plan

1. 新增 Skill、OpenSpec delta 和评测输入。
2. 在主入口接入路由，更新文档索引和 Skill 数量。
3. 运行静态契约、OpenSpec 严格校验和仓库既有测试。
4. 保留活动 change，交付实际文件、验证结果和限制；用户明确确认完成后再同步当前 spec 并归档。

## Open Questions

无。触发阈值和最小评测范围已由本设计确定，后续模型差异属于行为评测范围，不改变本次契约。
