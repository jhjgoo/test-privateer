# Design

## Context

`ask-matt` 的可借鉴点不是其工程生命周期，而是导航写法：主流程、入口、独立能力、词汇层、上下文纪律和反例都稳定分层；路由摘要只用于定位，判断前读取目标 Skill。当前 `test-privateer` 内容完整，但结构呈长段落叠加，主线与入口的区别不够明显。

## Goals / Non-Goals

**Goals:**

- 降低主入口认知负担，让用户请求先落到稳定层次，再进入细节规则。
- 保留现有 27 个 Skill 和各专项权威边界。
- 让路由前后有可观察纪律：先读取目标 Skill，再陈述或跳过。
- 让长项目测试在阶段边界、新会话或上下文压缩后可恢复。
- 用少量输入验证高风险行为，不新建通用评测运行器。

**Non-Goals:**

- 不复制 Matt 的 idea→ship、triage、wayfinder、retro 或 phase boundaries 流程。
- 不把 `test-privateer` 改成无上下文的目录索引。
- 不把所有专项规则搬进主入口。
- 不要求每个请求都走完整项目主线。
- 不改变产品测试授权、资产位置或编号规则。

## Decisions

1. **以“主线／入口／独立能力／词汇层”重排主入口。** 这四个结构词稳定、低歧义，可映射现有内容，不新增流程语义。
2. **路由表只保留短路由。** 每行描述当前处境和入口；详细能力、反例和交付契约由专项 Skill 维护。
3. **路由前读取目标 Skill 作为硬规则。** 防止主入口凭旧摘要误判能力或建议跳过。
4. **上下文纪律放在主入口，细节仍由项目资产恢复。** 主入口只规定何时恢复 TCO、路线状态和最近产物，不规定宿主专属 token 阈值。
5. **捷径与反例集中呈现。** 用少量高价值例外防止完整流程扩张，不复制所有专项边界。
6. **行为验证选用四类输入。** 覆盖直达、宽泛请求、续会话恢复和路由前读取；沿用现有真实模型评测协议与证据位置。

## Risks / Trade-offs

- [重排导致既有规则丢失] → 实施前建立原规则到新结构的覆盖清单；除重复内容外不删除语义。
- [结构名引入新概念负担] → 使用一两个句子的本地定义，不要求用户阅读外部 Matt 词典。
- [“先读目标 Skill”增加加载量] → 仅在需要陈述能力、比较入口或建议跳过时读取；用户明确指定入口且无冲突时直接进入。
- [上下文规则被误解为自动压缩] → 明确由用户或宿主触发 clear／compact；Skill 只规定恢复动作和阶段边界。
- [静态检查漏行为] → 契约检查仅覆盖结构、路由和引用；行为用最小真实模型样本验证。

## Migration Plan

1. 为现有主入口规则建立覆盖清单。
2. 重写 `test-privateer` 主入口结构，保留语义并压缩重复解释。
3. 增加目标 Skill 读取、上下文恢复、捷径与反例。
4. 更新最小评测输入与判据。
5. 运行契约检查、OpenSpec 严格校验和必要的行为评测。
6. 交付结果并保持活动 change，等待用户确认。
