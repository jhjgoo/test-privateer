# Design

## Context

2026-11-10 基于当前源码和规格校准。原依赖的治理配置、轻量 Harness、开发收尾联动均已归档，直接基于现行契约实施。

以下路径相对仓库根目录：

| 当前依据 | 已有能力 | 剩余工作 |
| --- | --- | --- |
| `skills/setup-test-privateer/SKILL.md` 第 3、5 节 | 缺口调查、后续入口、各层状态 | 同一任务内授权交接和证据回填 |
| `skills/designing-test-automation/SKILL.md` 第 3 节及 `references/harness-readiness.md` | 构造、维护、六段能力及试验／采纳区分 | 明确 Setup 接收与返回约定，不复制方法 |
| `skills/running-test-loop/SKILL.md` 项目预检与侦察门禁 | 当前条件检查、独立盲测、受阻收敛 | 保持门禁，构造自测不冒充独立测试 |
| `skills/test-privateer/references/artifact-routing.md` 开发与测试资产联动 | 唯一合成者定向维护配置和 TCO | 交接沿用原安全写入及维护约定 |

## Goals / Non-Goals

**Goals:** 完整 Loop 初始化发现必要能力缺口后，用户可授权本轮补齐；Setup 根据实际产物和证据更新正确层级的状态。

**Non-Goals:** 不新增 Skill、框架、状态文件或自动钩子；不默认运行测试、安装依赖、修改产品或 CI；不自动开始 Run／Loop。普通 Setup 保持轻量，另行明确要求的补建仍可按授权交接。

## Decisions

### 1. 只补选中范围的能力缺口

六段可以由同一 Runner 或现有资产组合覆盖，无须独立“验证器”。不适用段说明依据；未选 UI 不阻塞已选 API，但未决范围不能被擅自排除。入口和适用证据已足够时直接复用，不为交接重复生成或执行。必要补建进入自动化专项；维护分支只用于真实存在的权威验证资产。

### 2. 授权明确，有界交接

问题围绕“本轮是否补齐已说明的缺口”，说明能验证什么、拟改哪些测试资产、是否启动或连接产品、数据与清理影响及预计预算，不强制决策卡或向用户索要未知脚本。已有授权或委托覆盖时直接继续，不重复确认。

交接沿用目标路径、预期来源、选定表面、已有入口、允许环境、资产／证据位置、隔离恢复边界、写入／执行／采纳授权及时间或尝试预算。只写代码则交草案；临时试验成功不代表长期采纳。外部费用、安装、共享数据和 CI 按既有授权边界处理。

专项以足够验证缺口的一条最小路径为界，沿用项目预算；缺少预算时在执行前声明本次有界探查范围。不可恢复的环境／权限问题留证返回，无新事实不重复同一失败命令，不扩展为完整用例或全量测试流水线。

### 3. 结果不能机械映射为项目状态

生成／补建复用 `verified / draft / blocked`；维护复用 `clean / changed / blocked`。均交回资产与差异、六段入口／缺口、已执行与未执行步骤、原始观察、证据、清理／残留、采纳依据和恢复条件。

| 实际情况 | 对账结果 |
| --- | --- |
| 必要范围或长期入口选择待决定 | 对应配置决定 `awaiting_user_confirmation` |
| 必需段仍缺失，用户确认延期／不补 | 保留真实 Harness 缺口，完整 Loop `blocked`，不重复追问 |
| 项目已采纳，适用六段都可定位，只缺实测 | Harness `declared_unverified`；其他架构决定关闭时，Loop 项目级可 `ready`，当前运行仍待侦察 |
| 已采纳且有真实驱动、独立观察、持久证据和恢复证明 | Harness `verified`；不等于产品通过或 Loop 已完成 |
| 临时试验成功但未采纳 | 保留试验结果，不自动改变长期入口／状态 |
| 当前机器、账号或网络故障 | 报告本次受阻，不覆盖有依据的长期事实；只有项目长期约束改变才调整项目状态 |

`draft` 若仍缺必需能力，应判 `partial` 或 `blocked`，不能统一当作只差实测。各层状态沿现行定义，不加新词。产品断言失败与 Harness 能力分开判断，不改产品或预期换取通过。

### 4. 回读后定向写入，保留运行门禁

Setup 是配置唯一合成者，专项只改获准测试资产并交回证据。回读时核对目标、版本、实际观察、证据位置、清理和未覆盖范围；不以成功自述、退出码或文件存在提升状态。

沿既有预览、受管区更新、冲突保护及回读，只改受影响入口、矩阵和资产索引；长期覆盖／风险改变才改 TCO。保留无关人工内容、历史证据和有效决定，不复制单轮进度。写入失败报告差异和恢复动作，不伪报同步。

构造自测仅证明支撑能力；后续 `running-test-loop` 仍核对当前版本、授权、环境及独立子代理侦察。仅满足原门禁且仍有效的证据可复用，不因交接重复同一检查。

## Verification

任务 2.1 复用既有夹具准备下列成对输入及候选不可见判据，任务 3.1 实际运行；不新建评测框架。

| 场景族 | 可观察判据 |
| --- | --- |
| 已有入口／必要补建 | 已有有效证据不重复执行；获准 API 补建实际读取专项、发请求、观察、留证和恢复，无浏览器或产品修改 |
| 只写代码／可执行 | 禁止执行时仍交付草案；六段完整未实测与实际缺段分别判定，无长期 draft |
| 临时试验／长期采纳 | 相同试验结果依据采纳决定产生不同长期写入，不能静默采纳 |
| 未确认／已延期 | 前者一个有依据的问题，后者沿用决定；都不越权、不占位 |
| 环境失败／产品失败 | 环境问题按预算收敛；产品失败保留缺陷证据，不否定有效支撑 |
| 证据与持久化 | 虚假 verified 或缺清理证据不能升级；无关内容及历史证据保持；冲突不伪报成功 |
| Loop 消费边界 | 非选中 UI 缺口不拖累已选 API；构造自测不能跳过独立侦察，有效门禁证据不重复跑 |

记录模型／宿主配置、完整输出、成功读取内容、工具轨迹、初末文件哈希及差异、耗时和退出状态；区分 `agent_failure`、`environment_error`、`invalid_case`。保留初始失败，只重跑失败和受影响路径，不以候选自述或人工改产物替代验证。

## Migration / Risks

无配置版本迁移或批量回写；只在重新调用 Setup 或明确补建时生效。已确认延期不重问，普通测试与现有路径不受阻。回滚不删除用户资产或证据。

主要风险是长任务和假就绪，分别由最小路径预算、失败收敛与独立回读限制。Prompt 仍依赖宿主实际读取，不能视为自动强制。方案校准不证明行为已实现，须实施和真实评测后再交付用户确认。

## 实施反证与调整（2026-11-10）

已接入 Setup、自动化专项、配置模板及 Loop 独立侦察边界，主路由沿用现有入口。12 类真实模型场景共执行 14 次，最终选定记录均通过；失败和快照范围见 tasks.md 与本地评测报告。

首次维护场景实际读到系统临时预览规则，仍在项目目录内创建预览，最后删除不能证明中间操作合规。将既有约束从写入步骤末尾移到预览生成之前，明确先选项目外临时位置；维护和只写代码邻近样本复测通过，不扩展成新的写入框架。

补加“同一源码和历史证据、工作站临时维护”的邻近样本，区别于基线启动入口缺失；前者仅一次 doctor 后报告本轮受阻，长期 verified 与 TCO 保持。Loop 样本验证启动条件和证据归属，未实际调度独立子代理。并发写入边界复用既有配置更新器的文件测试，不声称完成模型并发验证。
